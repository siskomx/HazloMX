# Connect external agents to Hazlo Mexa tools

## Current chat setup — October 13, 2026

Open **Conexiones**, create/open a project, choose the AI and select the program/document. Describe the intended result and what it is for in ordinary language; missing measurements, units and ambiguous targets belong in the conversation. Review any proposed change in Hazlo, approve it explicitly, and let the agent re-read the verified result before a follow-up. The current screen has no engineering input forms.

For PCB placement, select the saved board in Hazlo and use **get_workflow_status** to obtain **pcb_selection**. **inspect_selected_pcb** returns measured component references, values, footprints, sides, identities and millimeter positions in bounded pages. Clarify the intended component and destination in plain language, then use **propose_pcb_move** with its selection/component identities and explicit millimeter, inch or mil units. Hazlo captures a copy, requires approval, sends the move to Konnect, then saves/checks/exports with KiCad and reads the final saved board. For another change, call **read_verified_result**, then pass its job ID/hash as **base_job_id**/**result_sha256** to inspection and proposal. Both fields must appear together; the original selection remains unchanged. This edits saved copies; it does not control unsaved changes in an open KiCad window.

For a new CADCraft source, choose **Abrir dibujo y medir primero…** in Hazlo. **get_workflow_status** returns its opaque `drawing_selection`; **inspect_selected_drawing** reads the source hash, declared unit code, native counts and file-coordinate bounds. Gather the purpose and missing measurements in plain language, confirm unspecified source units, then use **propose_selected_drawing_change** with that selection and a typed request. The original stays untouched, and human approval remains required. Source changes or switching project folders invalidate the selection. For subsequent CADCraft drawing changes, first select and complete a drawing-copy operation in Hazlo. **get_workflow_status** identifies its `cadcraft` job; **read_verified_result** returns the verified report plus drawing units, original counts/bounds, output format and whether the output is editable. Explain the final report’s measured output bounds/counts, clarify the intended conversion or circle dimensions, and call **propose_drawing_change** with the project, completed job ID/report hash and typed request. Coordinates/radius use the verified drawing’s existing millimeter or inch units; convert user-confirmed measurements into those units. The next source is the actual saved DXF/DWG output, which Hazlo inspects again before approval. PNG outputs are not editable. Lossy conversion still requires explicit review; the tool grants no arbitrary paths, native commands or live-document control.

For an OrcaSlicer revision, first complete the reviewed STL/profile slicing workflow in Hazlo. **read_verified_result** returns its native report plus measured mesh, original STL units and verified machine/process/material settings. Confirm the intended bed type and initial bed temperature in Celsius, then call **propose_slice_settings** with the project, completed job ID/report hash and those settings. Hazlo revalidates the model and profile sources, captures them again, preserves physical geometry/source units, and requires fresh approval before generating verified 3MF/G-code files. This tool changes the bed settings while preserving the selected machine/process/material; choose new model/profiles through Hazlo’s existing selection workflow. It does not print or control a device.

For KiCad checks/exports, read a completed **KiCad** check or **Konnect** schematic/PCB edit with **read_verified_result**. Native KiCad/PCB results include a structured `checks` summary; electrical errors remain findings, not a failed execution. Confirm report coordinate units (millimeters, inches or mils), then call **propose_kicad_check** with the project, completed job ID/report hash and units. Hazlo revalidates the published software-saved source and dependencies, captures another copy and requires approval before native ERC/DRC and exports. The file kind determines schematic versus PCB checks; report units do not rescale geometry. PCB checks can refill zones and save their copy. No arbitrary paths, open-document changes or hardware effects are granted.

1. Build the desktop and `hazlomexa-tools.exe` together. The connector must be beside the desktop executable. The installer build prepares the release connector and includes it as a resource; installed acceptance is still pending.
2. Open a Hazlo project. For a schematic, use **Abrir esquema y ver qué contiene** to select the source folder and sheet without launching Konnect or an AI model. Select the identified Konnect/KiCad runtimes before proposing an edit. For a new solid or sketch, the agent can start by reading supported shapes, units, board names and limits without a source file. Select the appropriate runtime before executing the reviewed proposal.
3. Expand **Usar las herramientas de Hazlo con Claude Code o Codex** and choose **Permitir conexión al proyecto**. This grants access to the selected context and pending proposals. Your chosen agent may send that context to its cloud service.
4. Expand the temporary configuration. For Claude Code, use the displayed JSON as an explicit MCP configuration file, or in its supported project configuration. For Codex, use the displayed TOML MCP entry in the configuration for the intended client. Hazlo does not modify either client's global settings or read its credentials. See [Claude Code MCP configuration](https://code.claude.com/docs/en/mcp) and [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp).
5. Ask the agent to read capabilities/status and gather missing inputs in plain language. For a schematic, inspect the sheet and clarify ambiguous components. For a new rectangular piece, confirm its size and units; for Arduino, describe its function and confirm the board. A proposal appears in Hazlo for review. Approval and native verification occur in Hazlo; the agent has no approval tool. Histories label these proposals as MCP tool input without claiming a particular AI produced them.
6. Choose **Revocar conexión** when finished. Closing Hazlo or changing projects also revokes the connection; an old session cannot inspect the new project. Re-enabling generates a new local connection and token. The configuration remains valid while that connection is enabled, not across app restarts.

The endpoint is a local Windows named pipe, rejects remote clients and authenticates before accepting MCP. The token is temporary access to this connection; do not publish or commit a configuration containing it. Four simultaneous sessions are supported. The helper performs no engineering operation itself and cannot open a second writer for the project.
