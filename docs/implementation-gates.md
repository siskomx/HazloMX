Approval tests cover edits, consumed/stale approvals, denial, project switching, restart, and delayed cancellation results.

The combined proof exposed a Windows handle incompatibility: holding DELETE access on the staging directory makes FreeCAD terminate before loading its macro. The backend now holds a read/list pin during execution, then reacquires a DELETE-capable handle after process exit and compares volume/file identity before validation and publication. The regression suite retains both native execution and rename-denial checks. Full-disk behavior, actual kill during publication, UI/channel integration, package installation, local-model performance, and a second Windows environment remain unverified; all full acceptance gates remain pending.

Use these short proofs to settle the implementation questions in the [readiness research](research/2026-10-10-implementation-readiness.md). Build only the small component needed for a gate, then retain it if it passes. Do not build the full UI, a universal gateway, or multiple application adapters before the first operation is proven.

## G1 FreeCAD geometry and executable contract

**Depends on:** an officially provisioned, identified FreeCAD Windows x64 package. **Effort allowance:** 0.5–1.5 developer-days; timebox the invocation uncertainty first.

Demonstrate one app-owned script reading a fixed `input.json` from an owned working directory. Determine whether `.FCMacro` or a tested `.py` bootstrap gives reliable argument/error/exit behavior. Use the embedded Python runtime, native `Part::Box`, and no GUI import. Close stdin and verify the process terminates; do not rely on terminal interactivity.

Pass criteria:

- Inputs `(10, 20, 30)`, `(1, 1, 1)`, `(200, 200, 200)`, and `(12.5, 7.25, 3.5)` mm yield one valid solid.
- FCStd reopens with editable Length/Width/Height; STEP reimports with the same geometry.
- Extents agree within 0.01 mm. Proposed volume tolerance: the greater of 0.001 mm³ or 0.000001 times expected volume; confirm the chosen kernel's numeric behavior before freezing this tolerance.
- Changing Length in the reopened FCStd and recomputing changes the geometry as expected. This verifies parameter editing rather than a frozen imported solid.
- Script exception, invalid dimensions, missing input, failed export, and absent result never report success, even if the upstream process exits zero.
- Run identity is fresh, every output remains inside staging, and filenames with spaces, accents, and apostrophes work without code interpolation.
- A private configuration/module environment is demonstrated; user addons and untrusted Python paths do not run during this job.

Retain: fixed script, input/result fixtures, package fingerprint, actual invocation and termination behavior, geometry/reopen test. If isolated headless execution fails, investigate the official portable environment first; do not start writing a custom CAD kernel or unrestricted Python bridge.

## G2 Job ownership and cancellation

**Depends on:** G1 for the real child; use a controlled test child first. **Effort allowance:** 0.5–1 developer-day.

Pass criteria:

- Cancellation before dispatch produces no child. Cancellation during staging produces no published artifact.
- A child that spawns a descendant is terminated as one owned job within the proposed five-second bound; unrelated FreeCAD/Ollama processes remain alive.
- Stdout and stderr are drained concurrently under limits; a noisy process cannot deadlock the job or fill memory without bound.
- App crash and app shutdown close owned job handles. No orphan remains after the tested restart path.
- Denial, double approval, delayed output, and project switch cannot start or repeat an operation.
- A cancellation/publication race has one defined outcome: cancelled before commit, or completed with retained published artifacts.

Retain: backend state transitions, owned-process supervisor, descendant/noisy-child checks. Do not claim a Job Object is a filesystem sandbox. If nested jobs fail, solve that observed lifecycle problem before expanding adapters.

## G3 Project publication and crash recovery

**Depends on:** G1; integrate G2's cancellation boundary. **Effort allowance:** 0.5–1 developer-day.

Pass criteria:

- One reserved staging directory contains the complete artifact set and run identity. Published output is a whole run directory.
- Existing user files and existing output directories are never replaced by a new run.
- Interrupt before validation, before commit, and immediately after commit. Restart identifies incomplete staging or committed output without repeating generation automatically.
- Simulated failed/partial snapshot writes preserve the last readable state and do not promote incomplete output.
- Denial and path traversal, junction escape, alternate data stream, reserved name, and unauthorized UNC cases leave outside files untouched.
- A second writer is rejected; unknown format versions fail without being rewritten.
- Locked output, failed rename, and disk exhaustion produce an actionable failure and preserve inputs.

Retain: version 1 project/run schema and independent boundary fixtures. Power-loss durability, OneDrive/network shares, and concurrent writers remain outside the certified matrix until explicitly tested.

## G5 Ollama protocol and model benchmark

October 11 update: the user explicitly authorized Ollama cloud model evaluation as well as local models. Keep separate local/cloud profiles and explicit selection; no automatic cloud fallback. Kimi cloud passed 20/20 unchanged Spanish cases with 0.76-second warm median and 1.14-second warm p95. Qwen3 4B CPU/schema runs failed at 12/20 and 9/20. Its JSON-mode comparison passed ten fully specified cases before a clarification failed strict parsing; no offline quality pass is claimed. See [benchmark evidence](research/benchmarks/README.md) for reports, exact digests, observed cloud protocol differences, and unverified requirements. Real local and cloud streams are now retained and replayed at every byte boundary in regular Rust tests.

Protocol implementation progress: eight parser/HTTP and captured-stream tests pass. They exercise every byte split including accented UTF-8, strict proposal validation, duplicate fields, late/mid-stream errors, truncated EOF, model identity, remote routing rejection, bounded record/text/wire sizes, and preflight rejection before user-prompt transmission. The Reqwest 0.13.5 client uses numeric IPv4 loopback and disables proxies, redirects, retries, and idle connection pooling. Cancellation tests cover stalled headers and a stalled chunked body, observe server-side socket EOF, and return within one second. The complete proposal has a 120-second deadline. These are client-side fixtures; actual Ollama inference cessation and UI cancellation latency remain unverified. Captured real streams and the Spanish model benchmark are recorded above.

Test-harness finding: synchronously joining a server thread inside a single-thread Tokio test prevented HTTP cleanup from running, producing a false cancellation failure. Moving the join to `spawn_blocking` fixed the harness. A separate Reqwest-only probe confirmed request cancellation closes the socket before response headers; the production client retains Reqwest rather than a custom HTTP connection implementation. Do not use the original failed fixture to claim a Reqwest cancellation limitation.

Primary protocol sources: [generate](https://docs.ollama.com/api/generate), [streaming](https://docs.ollama.com/api/streaming), [errors](https://docs.ollama.com/api/errors), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), and [Ollama 0.35.1 response types](https://github.com/ollama/ollama/blob/v0.35.1/api/types.go). Installed-model metadata is checked for both `remote_model` and `remote_host`; a loopback API address alone does not establish local inference.

**Depends on:** explicitly provisioned local runtime/model; manual geometry entry remains independent. **Effort allowance:** 0.5–1.5 developer-days plus model download/runtime setup.

Choose a small local model only after checking license and actual fit. Record model digest, Ollama version, hardware/backend, options, and cold/warm measurements. The current PC has approximately 15.4 GiB physical RAM and Intel Arc graphics. Qwen3 CPU inference was measured; GPU inference and usable GPU memory remain unverified.

Protocol pass criteria:

- Recorded NDJSON fixtures work when every possible byte boundary splits the stream, including a split accented UTF-8 character.
- Mid-stream error after HTTP 200, malformed record, oversized record, premature EOF, and truncated JSON never yield an approved proposal.
- Cancellation makes the UI responsive within the proposed one-second bound, blocks all later effects, and separately measures inference cessation.
- Proxy/redirect behavior cannot send a local-only request to an unapproved host. Cloud models are rejected for the offline profile.
- Missing model fails clearly, without automatic download or paid-provider fallback.

Model evaluation: freeze a 20-case Spanish set before tuning. Include explicit dimensions, decimals, missing dimensions, ambiguous units, a hollow enclosure request, out-of-range dimensions, and injected instructions. Label each case with an acceptable result: exact proposal, clarification, or refusal. Proposed pass threshold: at least 18/20 acceptable outcomes; zero invalid/out-of-range proposal executions. Test deterministic host rejection separately—the model score cannot certify safety.

Record cold start and median/p95 warm time across repeated runs. Proposed usability budget: p95 complete dimension proposal at most 30 seconds on the intended machine, with a clear cancellation path. This is a planning target, not measured performance. If it fails, try a smaller compatible local model or keep manual operation available; a different provider must not change G1–G3.

Retain: parser fixtures, benchmark cases/results, exact runtime/model profile. No GPU acceleration or offline claim without the corresponding observed result.

## Implementation contracts to preserve

The following names describe the small proposed product boundary, not APIs already implemented:

- `create_project` / `open_project`: explicit user-selected local root; return backend project identity and format version.
- `start_proposal`: selected project/provider and user request; return job identity, snapshot, and stream attachment.
- `edit_proposal`: validated dimensions; mint a replacement approval identity.
- `approve_operation`: one approval identity; no caller-supplied replacement arguments or shell command.
- `cancel_job`: backend identity; idempotent local request with an explicit state outcome.
- `get_job`: authoritative current snapshot after listener loss/restart.
- `open_artifact`: committed backend artifact identity; resolve its path/version in Rust.

For the first operation, store operation/version, length/width/height in mm, adapter version, and backend-resolved destination. Jobs additionally hold project/provider/model identity, phase, sequence, timestamps, and terminal outcome. Provider wire state remains private. Never store credentials or executable Python in the project schema.

Unknown operation versions, unknown fields, non-finite/out-of-range dimensions, stale approval, and mismatched project identities fail closed. Generate the provider JSON schema from the same Rust dimension definition when practical; host validation remains authoritative. Compare the generated schema and frontend types through one contract fixture to prevent drift.

## Scope and schedule

The effort allowances total roughly 3–7 focused developer-days before setup and integration failures; reserve the remainder of a two-week sprint for provisioning, fixes, and the second environment. This is not a guarantee or an assumption that two developers are available. A failed early gate is a reason to revise scope before spending weeks on UI.

Preserve the broader 24-week roadmap as conditional tracks. Re-estimate after G6 using actual benchmark, packaging, and failure results. Defer automatic source builds, marketplaces, multi-project parallel jobs, cloud sync, broad model catalogs, ARM64 certification, firmware upload, and printer control.

No gate has passed through documentation alone. The next authorized implementation should begin with these bounded proofs and retain their working code and fixtures, rather than treating the research as a promise of zero future edits.
