# Selected desktop context for connected chat

Claude Code and Codex now receive the active workflow, selected source/component and relevant current form values on every chat turn. Previously the UI forwarded only the message and recovered conversation, so an agent could not know which box or component the person meant by "this". Source references use project-bound selection identities or verified result identities; arbitrary paths, runtime credentials and unrelated workflows' fields are not included.

Blank/whitespace-only fields become null instead of fabricated measurements. Nonempty values remain literal, including case, spacing and Unicode. Form values are context, not approval or authoritative measurements; the prompt says they may contain defaults and requires fresh Hazlo tool/result checks and confirmation of missing values. A previously selected CAD result is included only in CADPilot and only when it belongs to the current project. Stale current-job identities from another project are excluded. Current measured dimensions can therefore be re-read while gathering the requested change; sending a turn does not itself prepare or approve an edit.

The retained frontend gate builds TypeScript/Vite and runs the existing nine-workflow headless Edge IPC fixtures, capturing source hashes before and verifying them after the run. It requires the specific passing marker and a fresh receipt with 20 cases: all nine workflows for each provider, then a selected-box follow-up for each. Those follow-ups carry the measured result SHA/job identity, selected Other box, preserved 0.2/0.3 cm lengths, unknown height and the request to make it taller. No extra approval or CAD follow-up command is sent. The Konnect cases preserve a literal component value with leading/trailing spaces and Unicode. Project/provider/folder recovery, question/cancellation, streamed proposal approval, metric/imperial and existing workflow regressions still pass.

Reproduce with `rtk proxy python apps/desktop/tests/verify-agent-context.py`. The verifier rejects build/test failures, missing/zero-case receipts, changed source inputs and exported fixture credentials. `status.json`, command logs, the 20-case receipt and exact tested source are retained here. Backend behavior and shared tool schemas were unchanged by this frontend fix; earlier native engineering results keep their original scope.

This proves current desktop selection/draft context reaches both chat command callers. It does not prove that a signed-in model asks the right clarification or returns a successful engineering proposal, native interaction, live/unsaved-document editing or installed execution of this change.
