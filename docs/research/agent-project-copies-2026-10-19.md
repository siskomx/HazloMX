# Retained Arduino project copies

Typed Arduino Agent edit/save proposals now include a bounded new native project tree and an independent check through the installed Arduino CLI sketch reader. Hazlo keeps the existing chat and native editor; it does not introduce an editor or download a model/runtime for this check.

The host automatically locates a configured CLI, a registered portable CLI, or the CLI bundled with the registered Arduino Agent runtime. Preflight checks its identity/version, pins its executable digest and the original sketch-directory identity, and validates the source tree before preparing approval. Legacy serialized proposals retain their original identities and behavior.

The original native edit/save receipt and original open-buffer checkpoint remain separate immutable links. The subsequent copy captures closed project files byte for byte, including binary, hidden, empty and build files plus empty directories. Retained native text replaces the corresponding copied files using UTF-8 and its original line endings; approval discloses that encoding policy. Internal Hazlo task storage/configuration is excluded when the task resides inside the sketch tree. Source files and unrelated native tabs are preserved; an explicitly approved native Save still saves the active original through the IDE.

The disk capture is a later phase, not evidence of closed-file contents at the earlier edit timestamp. Before an unlinked capture can proceed, the native instance, active identity and all open buffers must still match the retained checkpoint. Closed files are pinned while captured. Case aliases, reparse points, unsafe paths, changed identities/verifiers and over-limit projects are refused. There are at most 256 files, 128 directories, 8 MiB per file and 32 MiB total, two fresh copy attempts and two native readback attempts per copy. Partial folders are preserved; new captures never overwrite them.

The copy manifest binds the approved input, original buffer checkpoint, source-directory identity, filenames/directories and every file digest. The host links a freshly validated capture separately from the original edit. Arduino CLI 1.5.1 then reads that same copy using `sketch archive --include-build-dir`, under an isolated local profile. Every returned archive entry must match the captured file bytes with no missing, additional or duplicate files. A separate check digest is linked before publication. Long Windows paths use extended spelling for the native NT reader; the initial end-to-end test exposed and reproduced that issue.

Recovery never repeats an uncertain edit or save. A linked capture can be checked independently of the original IDE/source folder. A linked completed check is validated locally without launching the CLI. Altered linked copies, conflicting manifests/checks and missing original admissions remain paused. A plausible unlinked folder is not adopted as the original capture. A missing capture can only create a fresh bounded copy after the original retained native state is confirmed again; it does not reconstruct historical disk contents.

The existing result reader and folder action expose the checked native copy through the current chat. Raw source, copies, CLI output and revealing derivatives remain local behind the existing task/recipient sharing boundaries. The copy check establishes native sketch-reader roundtrip and file identity. It does **not** establish external library resolution, successful compilation, GUI fidelity, physical function, current live state or the agreed overall task outcome. Those remaining plan items must stay explicit.

The [acceptance record](agent-project-copies-2026-10-19.acceptance.json) records 380 desktop-enabled Rust tests passing serially (76 environment cases skipped), 33 companion/profile/transport tests, the frontend build, approval facts and the headless task-chat fixture. The rebuilt production host and real authenticated Windows pipe pass edit/follow-up/save, retained files, later manual changes, independent readback recovery with the original connection/source unavailable, and modified-copy refusal.

The actual portable Arduino Agent window passes native edit/Undo, historical unsaved-buffer retention and the production host's two approved edits/copies using automatic detection of its bundled CLI. One earlier launch stopped at the memory floor during a simultaneous Rust build; the final run used the native program alone. Another run exposed focus-dependent application Undo after opening a header. The probe explicitly refocuses the owned sketch before its single Undo and waits for the exact original source and a newer revision; the passing run advances from revision 3 to 4. These are native-window/API checks, not visual screenshot review or GUI reopening of the copied sketch. No real provider or physical hardware is used. The installed application and installer remain unchanged.
