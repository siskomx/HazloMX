# Arduino Agent protocol gate

October 11, 2026. Real upstream Windows Agent 0.7.1, pinned commit `fea5bb6a28d689a2ddbd1c635e2e187703c22549`, in an owned offline Windows Sandbox. [Package/source identity](identity.json), [package extraction](package-result.json), [measured scope](status.json). No models or hardware mutations ran. This is a protocol prerequisite, not an implemented Hazlo Mexa workflow.

The 217,376,673-byte Windows archive independently matches GitHub's SHA256 `a02ccf9fb97fa1e88b421ace4387bb5d912abe622152fcef2a9b89cae2603f58`. The bundled bridge matches the pinned source after normalizing line endings; exact byte hashes differ. Agent was launched only in a separate guest profile with a copied toolchain and fixture sketchbook, preserving the host Arduino preferences.

[Actual protocol result](protocol-result.json) proves authenticated loopback health, router catalog discovery and sketch source read/write round trip. Missing/incorrect bearer tokens, browser Origin and an expired session return 401/403/404 before changing the fixture source. A controlled rotation of only the guest token followed by owned-process restart rejects the previously valid token; the new token reads/writes successfully. No token or application log was exported.

[Official Rust SDK result](sdk-result.json) proves `rmcp 3.5.1` connects through Reqwest 0.13.5, negotiates `2025-11-25`, discovers the real router and reads the exact filesystem source/path without modification. The raw probe negotiated `2025-03-26` separately. SDK configuration disables proxies, redirects, HTTP retries and expired-session POST replay, constrains the endpoint to numeric loopback, bounds SSE events and applies timeouts. This sample does not prove automatic bridge write replay or production cancellation/recovery.

The initial launch produced an Electron `EPIPE` GUI error despite successful protocol checks. Redirecting the owned app's console streams corrected startup. The editor then appeared with a Windows firewall prompt, which was left untouched. GUI certification remains pending. The offline IDE also reported an unavailable CLI daemon while attempting library downloads; this does not invalidate the measured source tools, and does not establish Agent compilation. Existing Hazlo Mexa CLI compilation remains independently verified. The guest was stopped after evidence retention.

Reproduction: run `rtk proxy python tests/arduino/agent_package_probe.py` to download/verify a fresh package using the checked-in identity, then `rtk proxy python tests/arduino/prepare_agent_sandbox.py` with the existing verified CLI data and Node available. Start/connect its generated owned Sandbox and inspect `guest-result.json` and `protocol-result.json`. The guarded `rotate.ps1` requires a successful redirected startup. Build the isolated SDK fixture with `rtk cargo build --manifest-path tests/arduino/rmcp-probe/Cargo.toml --target-dir target/arduino-agent-probe/rmcp-build`; copy its executable and required runtime DLL into the mapped fixture input before executing it through `wsb exec --run-as ExistingLogin`. Successful CLI dispatch alone is not a passing result; inspect the saved JSON assertions.

Next implementation: use the verified official SDK for typed software operations, validate the router's inner tool/action and backend-resolved copy path, bind edits to one-use approval, preserve originals, and verify publication/recovery. Exclude firmware upload, serial/device mutation and unconstrained tool dispatch. Token/session changes invalidate pending authority; do not blindly repeat uncertain writes. Additional board/library provisioning, Agent UI integration, cancellation and recovery remain unfinished.
