# Arduino Agent copy-edit workflow

October 11, 2026. Production Rust adapter and shared project/job implementation, official `rmcp 3.5.1`, Arduino Agent 0.7.1 in an owned offline Windows guest. No model or hardware operations ran. [Measured scope](status.json), [upstream/package gate](../arduino-agent-2026-10-11/README.md).

The Spanish **Editar copia del sketch · Arduino Agent** workflow connects to the fixed authenticated loopback endpoint, imports an explicitly selected local UTF-8 `.ino`, shows the captured original and editable proposed code, and requires explicit one-use approval. The backend supplies the inner router tool/action and copy path. The frontend cannot dispatch arbitrary tool names, firmware, serial commands or file paths. Tokens remain in backend memory and are omitted from snapshots/history. Reconnection changes pending approval; a changed token requires reconnecting and reviewing again.

Agent edits and opens a fresh temporary copy. Its source response and actual filesystem bytes must match the approved code, and its returned document URI must identify that exact copy. Only then does the existing nonreplacing publication mechanism accept Original.ino and Sketch.ino in the project. The imported original is never passed to Agent for writing. Both accepted files open in the existing read-only viewer. Run schema 4 preserves legacy FreeCAD 1/2 and CLI 3; older installers can reject new Agent runs, so use the current build for projects containing them.

[Actual adapter](adapter-result.json) proves copy editing, exact returned document identity, original preservation and cancellation before effects. The first adapter attempt rejected the selected document because Theia's URI representation differs from a literal URI string; [retained failure](adapter-first-test-result.json), [diagnostic](adapter-first-stderr.log). The corrected check parses the file URI and compares the exact Windows path; Unicode/escaped drive and wrong-document cases have regression coverage.

[Actual shared workflow](workflow-result.json) proves stale approval rejection, approval invalidation after reconnect, successful verified publication, approval denial, occupied-destination failure with verified staging retained, original/prior-output preservation and reopening Completed/Cancelled/Failed history without regeneration. Seventeen closed exported project files independently matched guest SHA256. [Export hashes](project-hashes.json).

Frontend fixtures prove connection/source gates, changes disabling approval, explicit code review, original viewing, project separation and no Agent model dispatch. [Fixture screenshot](frontend-fixture.png) is not native UI evidence. Fifty-two regular tests pass; ten standalone entries are ignored and the actual Agent fixtures are invoked separately. Tests reject unknown-effect fields, network source paths, oversized/invalid UTF-8, wrong output/source/version and disabled-auth health. Desktop/custom-protocol Clippy and the frontend build pass. The final authenticated-health revision was rerun successfully in fresh guest `89f6dade…`; earlier results and the initial URI rejection remain retained separately. [Installer build identity](build.json) does not claim an installed workflow pass.

Cancellation stops the owned client wait and prevents publication; it cannot promise to stop a write already accepted by the separate Agent process. The temporary copy is retained for review and late effects cannot mutate accepted project artifacts. A subsequent [real held-write-reply check](../arduino-agent-cancel-2026-10-11/README.md) passes: backend Cancel returns in 3.66 ms, owned client/executor stops in 30.40 ms, and the released reply causes no duplicate write or publication. Native UI latency, late server-write timing and Agent UI/installed lifecycle remain unverified. Agent's standalone GUI previously exposed a Windows firewall prompt that was left untouched; native certification is still pending. Other integrations and broader Arduino board/library provisioning remain unfinished.

To reproduce, build regular tests, then run `rtk proxy python tests/arduino/prepare_agent_sandbox.py --backend-tests <absolute-owned-target/debug/deps/hazlomexa-test.exe>`. Start/connect its generated guest and require `guest-result.json`/`protocol-result.json` to pass before running mapped `adapter.ps1`, `workflow.ps1` and `export.ps1` through `wsb exec --run-as ExistingLogin`. Inspect the JSON results and test logs; successful host dispatch alone does not prove a passed fixture. Recheck exported hashes before stopping the guest. Runtime fixtures refuse any username other than WDAGUtilityAccount.
