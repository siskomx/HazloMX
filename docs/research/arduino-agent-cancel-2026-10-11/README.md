# Agent cancellation after a confirmed write

October 11, 2026. Real Arduino Agent 0.7.1 in an owned offline Windows Sandbox. A fixture-only loopback forwarder routes the unchanged production endpoint to the real Agent and holds one successful write reply after verifying the filesystem effect. This is controlled backend/SDK evidence, not native UI latency. [Measured result](status.json).

The approved source was written once to the backend-created temporary copy. With that reply withheld, the shared workflow's Cancel call returned in **3.66 ms** and the owned client/executor stopped in **30.40 ms**. The client socket closed. Releasing the withheld reply produced no publication or duplicate write. The original remained byte-identical, no result file appeared in staging, and reopening recovered Cancelled. The separate Agent remained running after client cancellation. Six closed project files and the unaccepted working copy independently matched exported guest SHA256. [Hashes](cancel-hashes.json), [held reply](held-reply.json), [client close](held-client-closed.json), [released reply](held-released.json).

This sample confirms cancellation during an uncertain acknowledgement after the real write. It does not establish cessation of an already accepted server effect, a server write occurring after cancellation, native UI latency or cancellation during GUI interaction. The application deliberately preserves the temporary copy and prevents those uncertain effects from entering accepted artifacts. No production networking/adapter code changed for this test. No models, firmware uploads or other hardware mutation ran. The guest was stopped after export.
