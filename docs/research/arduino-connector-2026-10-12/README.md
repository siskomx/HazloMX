# Arduino connector compilation and saved-sketch follow-up

The `installed_arduino_workflow` example passes a **host preflight**, using the current release connector and shared workflow backend with Arduino CLI 1.5.1, privately provisioned AVR 1.8.8 and Uno `arduino:avr:uno`. This is not yet an installed Windows guest pass.

Actual SDK calls in [the retained project](host-preflight/calls.json) prepare two reviewed compile-only jobs. The first approved sketch uses `HIGH`; the second derives `LOW` from the verified saved sketch returned by `read_verified_result`. Actual ELF/HEX/sketch publication and readback pass, with one-use approval and MCP provenance. Unsupported board and arbitrary path fields are refused before creating a job. No approval token is exposed through the connector.

An approved sketch containing an undefined symbol fails real compilation without publication. A separate reviewed job is cancelled before approval. Reopening the project restores two Completed, one Failed and one Cancelled run; the second sketch hash matches its earlier readback, and all six earlier artifacts plus the original sentinel remain byte-identical. The retained project contains actual artifacts and four run snapshots. Hardware mutation, firmware upload and model inference are absent. Approval/dispatch uses the backend fixture, not GUI interaction.

The example builds and passes Clippy with warnings denied. The reusable package preparer now copies the six built examples, maps the identified CLI and private core read-only, and the guest harness copies them into owned NTFS folders before executing the installed connector. It verifies two successful jobs, compiler error, denial, restart recovery and project-preserving uninstall. PowerShell parsing and Python syntax checks pass. [Source/binary identities](source-inputs.json) bind this preflight.

The installed run subsequently [passes in a fresh Windows guest](../installed-arduino-connector-2026-10-12/README.md), including upgrade, initial UI/private-profile cleanup and project-preserving uninstall. Host RAM initially fell below the existing 3 GiB preparation guard; after the user closed unused browser tabs, available RAM was rechecked above the guard before preparation/start. The production installer stays unchanged (`705532b4…`); this work adds validation fixtures. Native engineering GUI, Agent installed workflow, broader boards/libraries and signed-in conversations remain unfinished. The full application goal stays active.
