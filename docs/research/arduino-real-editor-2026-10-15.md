# Arduino Agent native editor and chat proposals

The owned Windows test now passes against the pinned Arduino Agent 0.7.1 executable, after Windows was unlocked. The test uses an isolated portable profile and owned sketch, never the person's normal Arduino profile. Native buffer support no longer rests only on a controlled IDE API.

## Actual editor evidence

The native probe inserts an unsaved note through the IDE API, inspects the buffer through the authenticated companion pipe, changes its delay, invokes native Undo and verifies that the earlier note survives. It then changes the delay twice, from 1000 to 500 to 250. Native revision reaches 6, the final buffer is dirty, and the original file still contains its initial 1000 delay without the note. The visible editor shows the final 250 delay and retained note.

The compiled `owned_agent_editor_host` example then exercises the shared `inspect_open_agent_documents` and new `propose_open_agent_change` tools against that same real editor. It prepares two changes, verifies no source change before approval, consumes approval once, executes production workflow jobs and independently reads the native source and verified receipts after each. The editor visibly ends at delay 100 after the 250-to-200-to-100 follow-up sequence. Stale tool proposals and stale direct writes are refused, saved bytes remain unchanged and both completed schema-15 jobs recover successfully. These approvals are backend fixtures, not clicks in Hazlo or real-model conversation evidence.

## Corrections discovered in the real window

The first unlocked run stopped at the unchanged 1 GB memory floor. A later run acknowledged a setup edit without changing the source. Actual window inspection showed a read-only loose file inside a different temporary sketch workspace. In the bundled application, startup scans existing path arguments, including option values; placing private profile directories before the sketch caused the wrong workspace to be chosen. The supervisor now places the owned sketch first. The native probe also uses Arduino's `arduino-open-sketch` command if its workspace differs, rather than treating `openTextDocument` as a sketch-context switch. The [pinned native sketch opener](https://github.com/mixelpixx/Arduino-Agent/blob/fea5bb6a28d689a2ddbd1c635e2e187703c22549/arduino-ide-extension/src/browser/contributions/open-sketch.ts) loads the sketch and opens its workspace.

Opening a sketch can produce another window and companion. Probe selection now authenticates read-only observations and requires one matching name, revision and source, rather than counting registration files. Finally, the bundled Theia native Undo command is `core.undo`; the generic `undo` command is not registered. These are fixture corrections. Production source/revision verification and uncertain-write behavior were not relaxed. Failed windows have a bounded 30-second diagnostic grace period; Stop, desktop lock and the existing memory floor still stop them immediately.

## Product behavior and limits

All existing agent routes now advertise the native proposal tool for Arduino Agent only. A proposal requires freshly inspected instance/document/revision/hash values and revised full source. The host rereads the buffer before preparing a review, preserves the private connection through the existing one-use approval workflow and checks native state again at execution. Cancellation cannot silently authorize a new job or undo an accepted native change. No saved-file fallback, compilation, firmware upload or hardware access is granted. Arduino's own autosave setting still governs saving; the owned test explicitly disables it.

All 172 regular desktop Rust tests pass (55 ignored), including the actual MCP SDK catalog round trip with 30 tools, program scope, invalid requests and pre-discovery cancellation. Library/example Clippy, all 16 companion tests with the compiled chat-tool host fixture, the production build and the four-provider production-chat browser suite pass. Browser assertions cover native Agent scope, fresh-inspection guidance, human approval/review and the result handoff; they remain IPC fixtures.

The chat describes native sketch scope, asks the agent to inspect before proposing and rereads native state after completion. Saved-copy selection is explicitly labelled. The actual IDE test requires the native companion installed in that IDE; ordinary-user companion installation, real-agent conversation, Hazlo's native approval UI, broader user-interruption cases and current installer acceptance remain unfinished. KiCad and the other integrations retain their separate outstanding gates. Raw source captures, profiles, credentials, screenshots and logs stay under ignored build output.
