# Arduino runtime verification

October 11, 2026. First component proof for the expanded application goal; this is not a completed Arduino adapter.

The official [Arduino CLI 1.5.1 release](https://github.com/arduino/arduino-cli/releases/tag/v1.5.1) portable Windows x64 archive was downloaded under the owned `target/arduino-probe` directory. Downloaded archive bytes match both the GitHub asset SHA256 and the separately downloaded official checksum list. Its executable reports version 1.5.1 and commit 01f3d4f2b. [Result and executable/archive hashes](runtime-result.json), [release metadata](release.json) and raw version/config/compile-help output are retained here.

`tests/arduino/probe_runtime.py` asserts that the CLI's effective data, downloads, user and build-cache paths all resolve under the owned probe. It filters inherited Arduino configuration variables and GitHub credentials from the child environment and passes an explicit configuration file. These settings follow [official configuration documentation](https://docs.arduino.cc/arduino-cli/configuration). The first assertion incorrectly expected configuration at the JSON root; actual 1.5.1 wraps it in `config`. The corrected assertion passes; the earlier attempt is not a passing result.

The actual compile help exposes both compilation and upload flags. The adapter must construct compilation arguments itself and never accept upload, port, programmer, arbitrary build properties or generic model-supplied CLI arguments as part of a compile approval. CLI identification/configuration proof does not establish compilation, process confinement or artifact correctness.

The next component proof now passes: official AVR core 1.8.8 was installed only under the owned toolchain, with post-install and pre-uninstall scripts disabled. Its downloaded archive independently matches the checksum in the official index; see [core identity](core-identity.json) and [selected core metadata](core-selection.json). Dependencies are the official AVR-GCC 7.3.0-atmel3.6.1-arduino7, ArduinoOTA 1.3.0 and avrdude 8.0.0-arduino1.

`tests/arduino/compile_probe.py` creates a correctly named Blink sketch and explicitly compiles for `arduino:avr:uno`. Compilation exits zero and produces nonempty binaries. The ELF has the expected magic and every Intel HEX record passes length/checksum checks, with 924 firmware data bytes. A separate malformed sketch exits one, exports no binaries and preserves its source. [Results and artifact hashes](compile-result.json), actual CLI JSON and stderr are retained here. No upload command or physical device mutation ran; installed discovery tools are not claimed to have been sandboxed away.

The Rust `arduino` module now uses the production owned-process supervisor and an explicit minimal child environment. It checks CLI/core/board identity, rejects hardware-command arguments through its typed input, checks JSON completion, verifies bounded non-reparse outputs, checks AVR ELF headers and Intel HEX checksums/flash bounds/end record, and retains only the verified HEX/ELF outputs plus source/input/result in a fresh stage. A native Rust test passes valid and invalid compilation with an accented project path and cancellation before dispatch. This component currently supports only the verified Uno/core combination; other boards remain unfinished work.

Current backend validation passes: 42 regular tests, seven standalone ignored entries, and desktop/custom-protocol Clippy with warnings denied. The actual Arduino test was explicitly run and passed, independent of its ignored default entry. This does not prove native UI approval/cancellation, persisted multi-operation history or atomic Arduino publication; those are the next integration work. No AI model was evaluated.

Reproduction: run `rtk proxy python tests/arduino/probe_runtime.py`, then use its explicit `target/arduino-probe/config.yaml` for CLI `core update-index` and `core install arduino:avr@1.8.8 --skip-post-install --skip-pre-uninstall --no-overwrite`. Filter inherited `ARDUINO_*` configuration and `GITHUB_TOKEN` from the test child environment as the probe does. Run `rtk proxy python tests/arduino/compile_probe.py` after provisioning. The native Rust test additionally requires explicit absolute `HAZLOMEXA_ARDUINO_CLI` and `HAZLOMEXA_ARDUINO_DATA` paths to this owned runtime/toolchain and `cargo test -p hazlomexa --lib arduino::tests::actual_owned_compilation_and_invalid_sketch -- --ignored --nocapture`.
