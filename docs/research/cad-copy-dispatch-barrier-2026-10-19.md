# CAD copy checks share the chat dispatch boundary

Hazlo remains a simple chat coordinating native programs. FreeCAD's independent working-version reader, CADCraft's native copy capture/export reader and their explicit recovery paths now share the existing Stop/correction gate. Follow-up socket requests and native process startups hold the gate only through admission, then release it while awaiting the admitted result. They do not consume the original edit admission again. A paused CADCraft follow-up preserves its usable connection and request identity; admitted transport failures retain the existing fail-closed behavior.

FreeCAD's original-result lookup also uses the gate before submitting its native recovery task. Polling an already admitted task continues without turning a correction into a false cancellation or undo claim. Recovery that needs a new native request/check becomes durable visible busy work under the original job, using the shared task/revision and cancellation checks. Already linked CAD results are distinguished before starting that native recovery stage, so offline restoration remains available after Stop or a newer instruction. Missing or changed receipts/copies remain preserved, and no original edit is replayed.

The latter fixture closes its own socket before waiting for the test server's EOF. Existing admitted-result, correction, offline recovery and privacy tests remain passing. All-target desktop Clippy passes. The frontend and serialized proposal/report formats are unchanged.

The tests do not establish a new onscreen CADCraft conversation, visual approval/correction, arbitrary GUI fidelity, real-provider behavior or physical function.
