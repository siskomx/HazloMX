# Anchor confirmed CADCraft effects before later failures

This extends the host side of the existing [native completion facility](cadcraft-native-completion-2026-10-19.md); it does not rebuild or replace the isolated native runtime. New proposals require recorded native completion before a gated edit. Legacy input serialization remains unchanged, while the approved input binds the new requirement against journal downgrade.

The [sanitized acceptance record](cadcraft-anchored-completion-2026-10-19/acceptance.json) comes from the rebuilt `cadcraft_checked_chat` example against the pinned isolated GUI and CLI. It verifies four completed edit/export jobs, native dispatch anchors, one-use backend approvals, metric/inch readback, native Undo, hidden-state refusal, independent DXF verification and restart recovery. The fixture preserves original reports/journals before simulating lost host result records. Recovery restores the original results while the later native document and session remain unchanged. Original source bytes and host settings are preserved, and the owned process exits. Native API checks do not establish a fresh visual inspection, real AI conversation or Hazlo approval UI.

The controlled transport test invokes the production gated run path and counts exactly one native operation before a final-report clash. After its server closes, local recovery restores the report without another native connection. A runtime catalog without recorded completion is refused before sending a write. Storage cases cover the missing report before and after acknowledgment, changed proof/report/conditions, attempted requirement downgrade, locked anchoring, unbound receipts, a missing dispatch record, occupied publication and preserved later user files. A new completion-version input cannot be adopted as legacy when its dispatch record is missing. New unanchored receipts remain paused; neither their contents nor a later matching observation alone establish the original reply.

Geometry reports can recover locally from the original native anchor. An unfinished export still needs a separate safe native reopen and is not silently verified during startup. Acknowledged exports can restore an identical missing report when output bytes still match. Recovery does not replace a changed report or output, repeat serialization, repeat an edit or query today's document as historical proof. The raw native receipt, including any serialized DXF, remains local under the existing exact-reference/service evidence boundary.
