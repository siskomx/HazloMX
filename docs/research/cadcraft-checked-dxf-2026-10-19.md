# Check native DXF reopening without following external references

New explicit CADCraft exports bind a versioned reopen-check scope into the approved input. The resulting report identifies the pinned native verifier, drawing units and model coordinate frame. It records native reopening, exact reserialized DXF byte equality and model-geometry checks separately from rendering resources, GUI state and physical function, which remain unchecked. Legacy inputs/reports omit the new optional fields unchanged and gain no invented verification.

The source audit found that the maintained native runtime's `open` command automatically loads block Xrefs. Its CLI has no safe-open switch. Before launching that CLI, Hazlo therefore inspects the bounded native ASCII DXF and refuses external-reference blocks, dependent symbols, external resource definitions, proxy/embedded executable objects and ambiguous structures. It also refuses encoded record names and encoded dependent-symbol separators: the native parser decodes DXF Unicode/MIF escapes even in structural names. Ordinary escaped Unicode symbol names remain supported. `BLOCK_RECORD` units are distinguished from `BLOCK` reference flags.

The captured file and its directory lineage remain pinned through the check. Hazlo compares the bytes read from the pinned file with the retained capture before opening it, pins the verifier and uses a fresh isolated profile whose directory lineage is also pinned. Three bounded native replies must confirm the original model geometry, units and exact DXF reserialization. Geometry-only agreement, a missing reply or changed bytes does not pass. Unsafe or unverifiable copies remain local without replacement or another native edit.

The original anchored native completion remains distinct from later export verification. Startup never launches the verifier for an unfinished export. Explicit recovery may recheck the already captured bytes read-only; it does not repeat serialization or the original edit. An acknowledged export can reconstruct an identical missing report only from its original bound completion and matching output. Versioned checks cannot be added to a legacy report or changed to claim GUI/physical verification.

This is a checked **explicit export**, not yet an automatic working version for every CADCraft edit. Exact byte equality concerns the native serialized DXF representation; it does not prove preservation of arbitrary original DWG features, every dependency, view state or physical function. Other saved CADCraft input/DWG open paths still need their own dependency policy before they can make this safe-open claim. Unsupported content stays pending. Raw native evidence, including diagnostics and serialized files, remains local under the existing exact-reference/service sharing gate. No provider or hardware is used, and no models are downloaded.

Validation passes 360 tests across the three desktop-enabled Rust suites (76 environment cases skipped), all-target desktop Clippy, the frontend build and source-derived approval-language checks. The explicit opt-in native verifier case also passes with both metric and inch fixtures. It confirms exact native DXF byte equality in addition to geometry and units. Regular tests refuse a retained external-reference export before any verifier/profile is started, malformed/encoded dependency structures, altered verification flags and attempts to retrofit legacy receipts.

The [sanitized native acceptance record](cadcraft-checked-dxf-2026-10-19/acceptance.json) comes from the rebuilt production-host example and the existing pinned isolated runtime. Four completed native jobs retain their original completion anchors. The explicit export includes unsaved state, passes the new native copy checks and remains recoverable after simulated loss of host results. Original source bytes and host settings remain intact, and the owned native process exits. This is native API/backend-approval acceptance; it does not establish fresh visual, real-provider, installed-app or installer acceptance. The installed application and installer are unchanged, and the full goal remains active.
