October 12, 2026. Identified CADCraft CLI 0.5.0 on the Windows host. No model turn, hardware effects, installation or live GUI mutation ran.

The earlier adapter verified circle counts, file identities and signatures. One additional circle with the wrong centre or radius could satisfy that check. The pinned native CLI exposes `entities` with circle geometry, limits and offsets; `readonly-cli-probe.json` retains its actual original/result responses. Hazlo now uses that native read operation through the existing owned-process supervisor, runtime pins, private profile and cancellation boundaries.

For a circle addition, Hazlo scans the original and edited native drawing in bounded 512-entity pages. It compares centre X/Y/Z and radius with the reviewed request, allowing only small numerical roundoff (`1e-8 + 1e-12 × max(abs(actual), abs(expected))`, in the drawing's units). The number of matching circles must increase by exactly one. This handles an already existing identical circle. Page totals must agree with the independently inspected circle counts; missing, inconsistent, oversized, empty premature or nonfinite geometry fails closed. Final DXF/DWG is opened again through the CLI and must retain the same match count before publication. For PNG, the edited native drawing is checked before rendering; the image does not receive a fictitious native entity readback.

New captured inputs and reports use schema 2, with a bounded `circle_readback` record. A schema-2 request rejects a version-1 count-only report, missing proof, incompatible counters or an inconsistent final summary. Version-1 saved runs remain readable with their original scope and unchanged files. This proves the requested circle's geometry and multiplicity; complete preservation of other geometry, properties, blocks, layouts and constraints remains unverified.
