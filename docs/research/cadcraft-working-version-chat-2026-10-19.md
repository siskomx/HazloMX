# Include a checked CADCraft working version with each edit

New typed CADCraft geometry proposals include a host-owned DXF working version in the same approval. Hazlo remains a chat: the native program performs the edit, retains its original completion and returns an atomic native observation. A separate recorded `document.bytes` call uses that exact returned binding, so native preflight refuses a document/context change before serialization. This reuses the already selected maintained runtime; it does not rebuild, install or silently select another program.

The approved input binds the working-version requirement. The original edit report remains immutable and separate from `DrawingVersion` capture and verification. The capture's exact native receipt is linked to the original dispatch only after matching the actual native reply, original document/geometry and unchanged native drawing/unit readback. Its serialized bytes remain local. Missing or unanchored capture evidence stays pending; recovery never assumes today's document is the historical state, silently recaptures it or repeats the original edit. A fresh capture after that blocker still needs a future scoped checkpoint/reconciliation path.

Once capture is anchored, its existing bytes can be checked independently in a pinned isolated native CLI. The check preserves source scale, compares model geometry, requires exact native DXF reserialization and compares the native metadata exposed by `drawing.inspect`: layers/current layer, named linetypes/styles/blocks/layouts, counts, extents, skipped records and model-space context. Native `notSaved` loss reports and unknown serialization reply fields are refused. The existing DXF dependency policy runs before native open, and file/runtime/profile/directory pins remain held through verification.

The manifest identifies the native verifier and this metadata scope explicitly. Named-table/layout inspection does not check every definition/property, arbitrary DWG features, rendering resources, GUI fidelity or physical function. Source preservation means the live drawing and original file are retained; it is not a claim that every original feature has been independently certified in DXF. The result reader marks the proof as a historical copy check and leaves the agreed task outcome/current live state unchecked. The full reply uses the existing exact-reference/service evidence boundary; filenames, raw diagnostics and revealing derivatives gain no sharing exception.

Capture and successful reopening have separate dispatch anchors. Startup can reconstruct the original edit report while keeping an unfinished copy check pending. Explicit recovery can verify only the retained capture in a fresh isolated profile; it never repeats native serialization or editing. An already anchored check can restore an identical missing copy report locally when its canonical bytes and captured file match. Changed reports/captures/copies and occupied publication destinations remain untouched. Repeating recovery of a completed matching proof is harmless; changing its scope or proof is refused. Legacy inputs/journals/reports omit the optional new fields unchanged.

Chat approval facts and technical details show the included copy and its limits. Completed batches offer the version folder without automatically opening a native document. A failed/interrupted copy check prompts the agent to recover the existing result, while cancellation retains its existing pause/readback behavior. No new program picker, editor, arbitrary shell route, hardware permission or model download is introduced.

Validation passes 363 tests across the three desktop-enabled Rust suites (76 environment cases skipped), all-target desktop Clippy, the frontend build and source-derived approval checks. Recovery cases distinguish uncaptured, unbound, captured-but-unverified and checked versions; changed copy/capture/check data; occupied publication; missing edit/copy reports; and idempotent proof recovery. Native loss metadata, missing/changed exposed source metadata, invalid scope and legacy serialization are also covered. The explicit opt-in native case passes with both metric and inch drawings, including the new metadata and exact DXF-byte checks.
