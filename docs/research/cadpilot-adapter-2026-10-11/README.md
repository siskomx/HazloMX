# CADPilot fixed selected-copy adapter

October 11, 2026. Source now contains a Rust capture/owned-process adapter and fixed FreeCAD macro using the identified CADPilot 0.7.7 primitive files with FreeCAD 1.1.4. This is adapter evidence; shared jobs, approval, publication, recovery and frontend binding are not implemented yet.

The adapter captures the selected original and exact five upstream module bytes into private job sources. It pins file/directory handles during reads and execution, rejects changed module identities, uses private FreeCAD configuration and the existing owned-process supervisor, and checks source/output hashes after execution. The macro exposes no RPC listener or arbitrary Python/property/expression operation. Requests are typed numeric inspection, box dimensional editing, box creation or cylinder creation with mm/cm/m/in/ft normalization.

Before loading any document, a bounded ZIP/XML policy validates the native object/property/extension catalog and captured BREP references. Python objects/properties/extensions, expressions, external dependencies and uncertified resources are rejected. The initial supported documents contain independent native Part primitives; GUI persistence, linked documents, assemblies, PartDesign histories and broader document fidelity require separate verification and are rejected where unsupported. This limit must remain visible when the app workflow is connected.

The captured original remains unchanged. Only `Working.FCStd` is deserialized. Mutations use enabled undo recording, verify all unselected measurement reports, read back native approved parameters and abort on errors. Successful edits produce a checked native document and STEP; saved FCStd is reopened and compared, and STEP solid count/volume are checked. Near-zero centre-of-mass noise from BREP reopening is accepted within 0.000001 mm; all remaining saved measurement fields compare exactly. The Rust adapter independently binds operation, job, source, normalized parameters, catalog/measurement invariants, expected target volume and output hashes, and rejects unexpected files.

## Evidence

- [Rust adapter status/source hashes](status.json), [stdout](stdout.log), [stderr](stderr.log). `rtk proxy python tests/cadpilot/verify_adapter.py` invokes the actual ignored Rust test serially. It executes under the production owned-process supervisor with real sources/runtime, verifies inch-based native editing and original preservation, then rejects a deliberately tampered STEP. Its final private test stage is intentionally tampered; it is not clean publication evidence.
- [Fixed macro nine-case status](copy-status.json) and retained `cases/`: inspection, inch-based box editing, centimetre-based box creation, millimetre-based cylinder creation, rejection of expression-valued parameters, arbitrary execution, missing selected object, uncertified archive content and an occupied output. Negative cases assert that loading never created a working copy. Reproduce with `rtk proxy python tests/cadpilot/copy_probe.py`.
- `rtk proxy python tests/cadpilot/test_policy.py`: two tests with multiple adversarial request/archive variants pass, including Python deserialization types, escaping BREP references, expressions and unexpected code/resources.
- Current regular backend suite: 67 passed, 21 separately scoped ignored entries. Desktop/custom-protocol Clippy passes. No frontend changes were made in this adapter step.
- [Earlier primitive/fresh-process gate and disabled-undo failure](../cadpilot-primitives-2026-10-11/README.md) remain separate evidence. During adapter work, native cylinders required the exact built-in `Part::PrismExtension`; an initially strict validator rejected it. Reopening also revealed approximately 1e-16 mm center-of-mass noise; neither observation justified relaxing other deserialization or geometry checks.

Remaining: usable app request/inspection preview, shared one-use approval and publication/recovery, pending/cancel races and live cancellation/timeout evidence, broader native document/GUI fidelity and upstream interactive operations, actual native desktop acceptance, installed lifecycle and second environment. The complete multi-integration goal remains active. This fixed file adapter does not certify the stock broad RPC endpoint or native addon interaction state.
