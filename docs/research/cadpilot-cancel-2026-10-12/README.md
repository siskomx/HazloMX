# CADPilot cancellation with observed native FreeCAD processes

The actual approved selected-copy box edit now passes live backend cancellation with CADPilot 0.7.7 and FreeCAD 1.1.4 on this Windows host. The test first captures the original, obtains the measured proposal and consumes its human-approval capability through the shared Workflow. It starts production execution and waits until both the owned launcher and its native FreeCAD child are independently observed alive before requesting cancellation. Native UI input remained stopped throughout.

In the retained sample, launcher PID 30988 and native PID 20352 both ceased independently after cancellation; the backend returned Cancelled in 15 ms. No result set was published, all artifact lookups were refused, the approval could not be reused, and the selected original remained byte-for-byte unchanged. Closing the workflow and reopening the project recovered exactly one Cancelled run. See [actual cancellation receipt](fixture/cancel-evidence.json), [retained project](fixture/project/hazlomx.json), [runtime identities](runtime-identity.json) and [exported file hashes](file-hashes.json).

The actual CADPilot adapter/publication runner now includes this cancellation case rather than silently filtering it out of its expected count. `rtk python tests/cadpilot/verify_adapter.py` passes all three native cases serially. [Status and exact source hashes](status.json), [stdout](stdout.log), [stderr](stderr.log) and [tested source](tested-source/tests/cadpilot/verify_adapter.py) bind this gate. Separately, 114 regular Rust tests pass with 33 explicitly ignored entries, and all-target custom-protocol Clippy passes. Production execution code was unchanged; the process-inventory extension is test-only.

The 15 ms sample measures the backend cancellation request through worker completion. It does not establish native UI latency, the exact point of mutation, cancellation during proposal inspection, or the full 120-second production deadline. Broader native document fidelity, interactive RPC/live unsaved editing, installed GUI acceptance and signed-in agent conversations remain unfinished. The frontend installer rebuild still requires closing the open Hazlo test window; this backend test does not satisfy that separate gate.
