# Approval-to-result conversation handoff — October 13, 2026

The production approval button explicitly requests both the native operation and a subsequent review by the selected AI. After a successful terminal job, Hazlo sends one follow-up asking that AI to call `read_verified_result` for the exact job and explain the actual change, checks and saved-copy limitations. The agent is instructed not to prepare or execute another change. Existing host tools and human approval boundaries remain authoritative: this handoff does not grant execution or automatically approve another proposal.

The pending request exists only in memory and binds the current revision, exact project UUID/folder, provider, selected program and job ID. It waits until the command, native work and existing conversation are idle. Failed/cancelled jobs, a rejected approval call, context changes or cancellation do not start a review. The request is consumed before sending; duplicate terminal events cannot replay it. Opening an existing result or restarting the app does not trigger a provider request. The review uses the existing cancellable chat route and session/context behavior; it can consume the selected provider's plan as disclosed in connection setup. A failed review is shown through existing chat error handling and is not retried automatically.
