# Codex questions in Hazlo chat

October 12, 2026. Ordinary `item/tool/requestUserInput` requests now connect the installed Codex app-server to Hazlo's desktop chat through `run_with_questions` and the bundled-view-only `answer_codex_question` command. The [upstream app-server protocol](https://learn.chatgpt.com/docs/app-server) and the installed 0.159.2 experimental JSON schemas define the request and answer shape.

Questions are bound to the native thread/turn and the current Hazlo project/chat/question IDs. Hazlo shows one to three literal questions with choices or text inputs, preserves unfinished input during polling, and sends only validated, explicitly submitted answers. Choices have no default selection. Free-text questions with choices offer suggestions and accept another answer. Successful submitted answers remain in the displayed conversation. Questions cannot grant engineering approval or collect secrets. Missing, duplicate, oversized, foreign-session and invalid-choice input is rejected. Cancellation, native request resolution and terminal completion close the pending question; there is no timed default answer. Ordinary Codex requests in this version are marked `isBlocking: false`; the adapter accepts the typed flag and monitors native events while awaiting the human. Partial JSON records survive an answer interrupting the pending read.
