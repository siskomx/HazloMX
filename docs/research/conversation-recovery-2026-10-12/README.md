# Bounded conversation recovery and fresh agent context

The current source saves the visible chat transcript locally by project ID, exact folder and provider/workflow. It accepts only version-1 user/assistant text, bounded to 8 KiB/128 messages, with deduplication IDs and a new-session preference. Invalid, oversized or unavailable storage never creates an operation; the app continues in memory and reports when it cannot save the full history. Text renders literally. No approval token, pending question, bridge configuration or provider credential is stored by this mechanism.

The desktop snapshot now reports whether each provider has a successful native session for the selected project. A warm session continues through the existing client resume route. When that session is unavailable after restart, cancellation/failure or runtime reselection, the next user submission starts fresh and includes the saved transcript as context. The prompt explicitly requires current project/tool/result inspection and fresh confirmation; saved text is neither an approval nor a current measurement. It is byte-bounded before sending, and no agent request occurs merely because history was restored.

`Nueva conversación` clears the current scoped history and preserves its fresh-session intent across provider switches/reload. Claude and Codex completed responses are tagged by provider so another provider's last response cannot enter the displayed/stored transcript. A copied folder sharing the original project ID receives a distinct history scope. Native thread IDs remain process-local; this restores visible conversational context, not the upstream client's hidden tool memory or a stopped question.

The expanded nine-workflow browser gate passes recovery after clearing browser session storage and restarting the mock backend, restored text in the fresh Claude request, literal injected content, copied-folder isolation, provider isolation, new-conversation reset, existing approvals, questions/cancellation and unit handling. It also checks malformed/system-role/oversized stored data and the 8 KiB send boundary. [Recovered view](conversation-recovered.png) was visually inspected; the IPC is mocked. A separate desktop Rust test proves readiness is false for pending/foreign-project sessions and true only for a successful current-project session. The 110 regular Rust tests, desktop test, formatting, all-target/desktop Clippy, production frontend and desktop/helper builds pass.
