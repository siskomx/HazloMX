# FreeCAD retained-copy check-only resumption

Hazlo remains a chat coordinating native tools. This change extends the existing check-only approval to a retained FreeCAD native version; it adds no design editor or geometry operation.

The proposal binds the original admitted operation, its anchored native completion, exact capture/file and retained directory identity, current task conditions, matching reader executable digest and recorded attempt count. A fresh approval authorizes one additional independent reader check, limited to 90 seconds. At most two checks may be recorded for that copy. Historical checks made before attempt recording remain unknown; they are not described as unused permission. Existing PCB and Arduino input identities and their original attempt allowances remain unchanged.

The host automatically resolves an existing compatible FreeCADCmd from remembered/portable/installed locations. A different binary is skipped rather than assumed compatible. The same retained file is opened and recomputed in a private native reader profile. No original editor, source document, recapture, edit, Save As or model download is involved. The immutable capture and native file stay pinned. The Windows launcher receives normal drive-path spelling for its working directory, while host file validation retains extended Windows paths and directory pins.

An attempt is durably reserved with the new approval identity before dispatch. Completion links are written only after owned-process closure, the launch-specific receipt and native properties/geometry checks. An uncertain attempt is consumed, never replayed. Unknown/modified tickets, changed copies, mismatched readers, missing original links and exhausted recorded bounds preserve the work and pause. Stop and task corrections fence later dispatch; a changed task invalidates a prepared approval. Publication can move the retained directory without changing its native identity.

Completed reader proof can repair a lost parent check link and recover reports locally after restart without launching a reader. An existing differing report remains untouched. Arduino now uses the same bounded reader ledger with its serialized ticket format preserved. Raw copies, reports and derivatives remain subject to the existing task/service sharing gates.
