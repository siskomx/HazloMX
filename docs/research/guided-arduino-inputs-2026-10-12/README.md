# Arduino chat gathers confirmed inputs before producing code

Follow-up uncertainty correction: “no sé”, “no se” and “I don't know” now continue the missing-board or missing-timing questions rather than being treated as refusals. Explicit Spanish/English negation, including a typographic apostrophe, still preserves the draft. New regressions verify these questions, a subsequent confirmed 250 ms answer and uncertainty combined with an explicit refusal. The frontend production build and all nine workflow browser fixtures pass on this follow-up; [follow-up source hashes](uncertainty-source-inputs.json) identify the changed helper and tests separately from the original evidence below. Packaging remains blocked by the open native executable, and native input remains stopped.

Guided Arduino chat previously treated any mention of blinking as a request for a fixed LED_BUILTIN/500 ms sketch. It now asks for Arduino Uno, the integrated LED and the interval before producing the example. Missing inputs leave the existing code intact. Short follow-up answers work within the explicit question chain, including after conversation recovery; unrelated conversation history does not become a recipe.

The helper handles confirmed Spanish/English second or millisecond values, including decimal comma. Decimal seconds convert exactly to whole milliseconds: `1,001 segundos` becomes `1001`, without floating-point rounding of the user's value. Zero, negative, sub-millisecond and out-of-range intervals remain questions. Conflicting on/off timings ask for one interval; a later explicit interval replaces the ambiguity. Negated and external-LED requests preserve the code and ask for the needed context or use of an installed assistant/custom source. This remains a bounded integrated-LED recipe, not general natural-language code generation.

The Send button was already disabled while a proposal awaited approval. The handler now also preserves reviewed code if a form submission is dispatched directly; busy/reviewed jobs cannot receive a replacement recipe. No proposal, approval, compilation, model or hardware effect is triggered by these guided replies.

TypeScript/Vite and all nine workflow browser fixtures pass. New regressions verify staged questions, confirmed timing, decimal comma, English milliseconds, invalid corrections, ambiguous intervals, draft preservation and reviewed-code protection, with no extra inference calls. [Browser fixture](browser-fixture.png) is browser-only evidence; [source hashes](source-inputs.json) bind the tested change. Native UI was kept stopped after the user's Escape interruption.
