# Link KiCad worker replies before later failures

New typed live PCB move/export proposals bind a native-completion requirement to the approved input. The existing bundled worker already retains an input-bound receipt before replying. Hazlo now validates the core returned result, matches it against that retained receipt and links its exact bytes to the admitted dispatch before later export-file checks or final report storage. This reuses the existing worker/native SDK protocol; no program upgrade, installer, model or arbitrary command is introduced.

The original result and later artifact/report checks remain distinct. A confirmed worker reply counts as acknowledged while an occupied report or missing/changed export keeps the job under review. Recovery uses the linked historical receipt, validates any retained export against its original identity and reconstructs only an identical missing report. It does not contact the editor, repeat a move/export, regenerate a missing copy from today's board or replace changed files. A missing dispatch, never-admitted call, changed agreement, mismatched worker reply/file, altered proof or changed expected report digest cannot supply an original link. A locked journal preserves the worker receipt and consumed dispatch; the trusted reply can retry identical bookkeeping after the lock is resolved.

Raw unbound receipts remain paused, including older uncertain attempts. Completed legacy records remain readable without invented native anchors. An existing final report can still be checked against its original acknowledged hash without requiring an old worker receipt. If that report is missing, a legacy worker receipt may restore it only when its canonical result matches the original acknowledged report hash exactly. New proposals cannot use that legacy route or drop their version requirement. Unknown outcomes never gain another mutation attempt through recovery.

Startup and explicit recovery share these checks. New result replies identify a historical native PCB receipt, with guidance to inspect fresh state before further work. Failed/interrupted chat batches request retained-result recovery instead of another movement/export approval. The complete report and derivatives continue through existing task/service sharing gates; restricted component values, paths and raw native data gain no exception. The software receipt does not establish current board state, physical behavior, every dependency, native concurrency isolation or the agreed task outcome.

The [sanitized controlled acceptance](kicad-anchored-completion-2026-10-19/acceptance.json) uses real SDK objects, NNG/protobuf and the bundled frozen worker against an owned simulated KiCad server. The rebuilt production host performs two approved moves, checks native reply anchors and preserves the intentionally stale saved source. After the cached native helper is deliberately made unusable, the fixture archives both original reports and reconstructs their exact bytes through project restart recovery. All 18 worker tests pass, including duplicate receipt reservation without another native request and a separate native-protocol export. This is protocol/process/host evidence, not a real KiCad GUI or physical-board test.

Host fault cases separately cover occupied reports, absent/changed export files, receipt/reply mismatch, unbound valid-looking files, real Windows journal locks, invalid conditions/version, legacy acknowledged restoration and consumed admissions. Valid worker effects stay known while later checks remain pending. Raw fixtures, packets, receipts and logs stay local. Checked working copies with every PCB edit, broader native concurrency/dependency handling and the remaining simple-chat plan/release requirements remain active. Keep KiCad 10; live schematics stay pending. The installed app and installer are unchanged.

The complete desktop-enabled Rust run passes 370 tests (76 environment cases skipped), all-target desktop Clippy passes, and the frontend builds. The headless task-chat fixture checks failed PCB reporting produces a retained-result recovery prompt without another edit approval; its existing correction, evidence, other adapter and copy-output cases still pass. The SDK/frozen-process acceptance is explicitly run separately from the regular skipped environment cases. There is no fresh native-window, external-provider, hardware, installed-app or installer acceptance claim.
