# KiCad real owned-process cancellation and short deadline

October 11, 2026. Actual identified Windows x64 KiCad 10.0.7, production shared workflow and Windows owned-process supervisor. [Retained tests/source identities](status.json), [test output](stdout.log), [compiler output](stderr.log), [cancel sample](cancel-evidence.json), [deadline sample](deadline-evidence.json).

The cancellation fixture captures an upstream PCB/project/schematic/worksheet in a separate project, prepares and approves the actual operation, runs it on a worker thread, and polls the Windows process snapshot. It cancels only after observing an alive `kicad-cli.exe` whose parent is the test owner. The workflow returns Cancelled in 15 ms in the retained combined run (33 ms in the initial standalone run), marks itself idle, rejects report access, and publishes nothing. The observed PID is independently checked stopped after the worker returns; no other owned KiCad CLI remains. Original bytes are unchanged and reopening restores the Cancelled snapshot. This observes a live process during the command; it does not prove how far KiCad parsed or edited its private working copy before termination. Native Cancel-button latency remains unverified.

The deadline fixture runs an actual `pcb drc` on copied inputs with isolated configuration and a deliberately shortened 100 ms supervisor deadline. It observes the owned CLI PID, gets TimedOut, confirms that PID and other owned KiCad processes stopped, and verifies board bytes unchanged. The retained sample returns in 146 ms. This proves real-process startup/check termination through the supervisor. It does not claim expiry of the production adapter's fixed 120-second deadline or a long-running design-check timeout.

The existing project hierarchy, output/recovery and publication fixtures still pass. Run `rtk proxy python tests/kicad/verify_app.py` with the identified runtime provisioned. Its four ignored actual tests run serially to keep same-owner PID observations unambiguous. The evidence runner asserts every required test name, exit code and exact successful aggregate, allowing serial nocapture diagnostics between a test name and its standalone `ok` line. It rejects failed exit, missing tests and incorrect success counts with self-checks. The initial combined tests passed, but the older evidence parser incorrectly rejected their diagnostic layout; that failed harness record remains in the owned target run.

Current regular suite: 61 passed, 17 separately invoked ignored entries. Backend/test Clippy passes. These are host backend/supervisor results, separate from the earlier [native schematic workflow](../kicad-native-2026-10-11/README.md).
