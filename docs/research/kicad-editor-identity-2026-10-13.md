# KiCad native document identity — October 13, 2026

The existing PCB read connection now queries Konnect's typed `get_editor_state` before and after its two component observations. It requires the compatible native KiCad version and one addressable PCB editor with one exact matching saved document identity. Missing, duplicate, foreign or malformed contexts fail. Canonical document path and available native project identity become a fingerprint; the native paths/project name stay private. Standalone boards may have no native project, without inventing one. Later agent refreshes must match the originally selected document fingerprint.

The production chat passes this fingerprint with its opaque source capability. It does not treat the first open document as active, infer a foreground editor, or grant mutations. The fingerprint identifies the reported document/project, not a complete PCB revision or an editor instance across restart. Component hashes retain their narrower geometry projection scope. Source/live selection separation and private in-memory connection tokens remain unchanged.

## Native contract and implementation decisions

The exact identified **Konnect 0.13.0** binary successfully loads `editor_navigation` and exposes `get_editor_state` with the expected empty-object schema. The sanitized [metadata receipt](kicad-editor-identity-2026-10-13.json) records its executable hash and schema. This metadata probe makes zero editor calls and no UI actions. Production also checks the native schema before calling it; it does not expose the other native tools to the agent.

The pinned [Konnect board-write gate](https://github.com/mixelpixx/Konnect/blob/6bbe3e4f890ba1d37c0e5d5f38ccd03d90958c9e/crates/konnect-core/src/tools/pcb_board.rs) can permit saved-file fallback for an unavailable or different open board. Its ordinary component move therefore cannot be used as Hazlo's live-only write boundary. Checking the returned source after mutation would be too late.

KiCad 10.0.7 adds explicit document headers to both transaction boundaries in its [native command contract](https://github.com/KiCad/kicad-source-mirror/blob/10.0.7/api/proto/common/commands/editor_commands.proto). Its [handler](https://github.com/KiCad/kicad-source-mirror/blob/10.0.7/common/api/api_handler_editor.cpp) validates those headers and refuses legacy headerless transactions when multiple editor handlers are present. The pinned [Konnect client](https://github.com/mixelpixx/Konnect/blob/6bbe3e4f890ba1d37c0e5d5f38ccd03d90958c9e/crates/konnect-ipc/src/client.rs) sends headerless BeginCommit/EndCommit messages. A reviewed compatible native path is needed before enabling that broader live transaction flow. The upstream client has bounded late-reply recovery and warns that uncertain delivery must not cause blind retries or rollback; those semantics still need a Hazlo execution/reconciliation boundary and native proof.
