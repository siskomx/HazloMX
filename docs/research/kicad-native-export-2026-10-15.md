# KiCad open-board export — October 15, 2026

The shared chat tool `propose_selected_live_pcb_export` now prepares a separately approved editable copy of the current open PCB, including unsaved edits. It accepts the fresh native selection/instance/document/state binding and a description, with no destination, component, movement or units. Hazlo captures `Board.kicad_pcb` as a new project artifact, verifies its complete bytes against the approved native serialization, and rereads the unchanged open document. The catalog now has 33 tools; this proposal belongs only to KiCad.

The implementation uses KiCad's existing [SaveDocumentToString handler](https://github.com/KiCad/kicad-source-mirror/blob/10.0.7/pcbnew/api/api_handler_pcb.cpp#L1894), whose native serializer supplies the board contents. It avoids the [SavePcbCopy implementation](https://github.com/KiCad/kicad-source-mirror/blob/10.0.7/pcbnew/files.cpp#L1019), which also saves original project-local settings. The worker creates the destination exclusively, refuses existing files and stale bindings, and marks changed/lost final readback uncertain. It never calls native save, changes geometry, reroutes, touches hardware or packages external resources.

Movement and export are mutually exclusive inputs. Old movement snapshots/receipts remain compatible with schema 14; export requires an explicit flag and no movement. Its receipt requires unchanged instance, document, whole-board state and components, no native commit or original save, and an export hash matching the approved state. Publication and later artifact/report access revalidate the file and receipt. Tampered exports cannot be opened as verified results. Review facts explain the copy-only scope; the results action reveals the verified file through the existing artifact route.

## Reproduction and remaining scope

Build the frozen PCB worker with `tests/kicad/build_worker.py`, then the desktop-feature `ollama_pcb_live_chat` example. With the configured owned KiCad fixture root in `HAZLOMEXA_REAL_PCB_ROOT`, run `apps/desktop/tests/ollama-native-chat.py --run-real-cloud --program pcb-live --export-final-copy`. The existing five-turn/two-job case remains the default. The example's `--export-only` mode performs the owned two-job backend checkpoint without provider calls.

This is a board-file export, not saving the open document or exporting a complete project, external models/libraries or manufacturing files. It retains the existing bounded native reader's scope. Real-provider acceptance above uses the existing Ollama Cloud route and backend fixture approvals; native Hazlo approval UI, other providers, larger/complex board fidelity, ordinary-user installation and the current installer remain unfinished. The full multi-program goal stays active.
