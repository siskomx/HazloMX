# KiCad native-state working-copy fallback

The current typed PCB move route captures the open board through KiCad and edits a separate native working copy. The original editor and its saved file remain untouched. This replaces the earlier typed original-board move route; it does not certify concurrency isolation for arbitrary discovered MCP calls.

KiCad 10.0.7's [transaction handler](https://github.com/KiCad/kicad-source-mirror/blob/10.0.7/common/api/api_handler_editor.cpp) separates observation, item update and commit requests without a caller-supplied expected board state. Hazlo's previous final read therefore did not establish an atomic condition through the later commit. Its full-state post-check could detect some conflicts after effects, but could not guarantee preservation of a manual edit in that interval. New typed original moves are now refused before native dispatch. Historical receipts and their read-only recovery remain supported.

The existing move proposal keeps its native selection, instance/document/state identities, component identity and explicit units. Hazlo detects the registered/installed compatible Konnect and KiCad CLI runtimes and verifies them using existing checks. It uses the existing read-only native serialization/export route in a private local profile before approval, checks its exact state against the original observation, then captures project files using those native board bytes. It never substitutes the saved board. The shared dependency collector retains its existing limits and external-path refusals; original project files are captured separately from disk. A task/revision change during preparation prevents a stale proposal.

The ordinary approval explains the fallback, native-board provenance, saved-settings provenance, loss of pending settings from other windows and the unchanged original. After approval, the existing closed-copy Konnect/KiCad workflow edits and saves the owned copy, independently reopens/checks it, retains dependencies and reports native findings. That existing check refills copper zones on its checked copy; approval now describes that effect for PCB copies. Moving a component may disconnect tracks; successful editing/reopen does not establish electrical correctness, 3D resources, GUI fidelity, physical function or the whole task outcome.

The new optional native-origin and agreement fields bind the captured board digest, component position and conditions without changing legacy serialized inputs. They are shown through the existing chat review. Results label the captured original and new checked board accurately. Source-bearing results and derivatives remain behind task/service sharing boundaries. No provider or model download is introduced.

`read_verified_result` supplies `pcb_followup` with a selected verified result and its job/report identity. If the current task has no PCB selection after reopening, the host recreates one from its checked native artifact. A follow-up reads that exact base result instead of asking the person to locate a file. A failed copy remains preserved; the chat does not repeat its operation or replace it from today's original.

The actual program acceptance uses a disposable native window and copied owned test profile. After opening the public test board, the fixture deliberately makes its saved file stale. The first approved copy must therefore come from the native editor; a saved-file fallback cannot pass. It performs one move, an imperial follow-up on the checked result, independent native checks, original live/disk preservation and local job recovery. It also checks follow-up selection restoration in a fresh host context. This is a backend approval/native-window test, not a real-provider conversation or visual GUI reopen of the copied board.

The [acceptance record](kicad-native-working-copy-2026-10-19.acceptance.json) records 384 passing desktop-enabled Rust tests (76 environment cases skipped), all-target desktop Clippy, frontend build, approval-language assertions and the updated headless task-chat fixture. The real-window run passes both checked copies, the imperial follow-up, original preservation, recovery and restored follow-up selection; its supervised editor stops afterward. The installed application and installer remain unchanged. General MCP concurrency safeguards, incomplete-copy forward recovery, remaining program/outcome boundaries and Windows release acceptance remain active; KiCad 10 live schematics remain pending.
