# KiCad Windows checks and exports gate

October 11, 2026. Actual official KiCad 10.0.7 Windows x64 CLI in a private extracted runtime, with a fresh private configuration and copied design fixtures. This is the runtime/report-contract gate; the later [application binding evidence](../kicad-app-2026-10-11/README.md) covers app source and actual backend checks separately. Konnect remains unfinished. [Actual result and file hashes](result.json), [invocations and help](calls.json).

The schematic/PCB/project inputs come from pinned upstream QA, with [origin and hashes](fixtures-origin.json); the upstream test data uses [GPLv3](LICENSE.GPLv3). Minimal clean fixtures are authored in this repository. The stock library tables, symbols and footprints come from the same signed package and are mapped to the private profile. AI models and hardware controls are absent.

Verified behavior:

- Exact version and help for ERC, DRC, schematic PDF/netlist and PCB Gerber/drill commands.
- Both ERC and DRC JSON reports in mm, inches and mils; findings retain their type/severity and coordinates scale correctly.
- The upstream circuit reports two undriven-power errors and one cached-symbol mismatch warning. Its board reports five cached-footprint mismatch warnings. Disabled checks remain present in `ignored_checks`; they are not inferred to have passed.
- A pair of deliberately crossing same-layer tracks on different nets introduces real copper errors into a board whose baseline has no active errors. KiCad may label the contact `tracks_crossing` or `shorting_items` according to the detected geometry. The fixture accepts those concrete fault categories and verifies the baseline contrast, rather than mistaking library warnings for a copper defect. An earlier assertion requiring only `shorting_items` failed and remains in the owned target run; fixed track IDs and the documented geometry categories replace that assumption.
- Minimal clean schematic and outlined PCB return exit 0 and empty findings. Reports with findings return 5 when `--exit-code-violations` is used. Invalid board input returns 3 with no report. The completed-check outcome is separate from design findings, as specified by the [official CLI manual](https://docs.kicad.org/10.0/en/cli/cli.html).
- Schematic PDF and XML netlist, three explicitly selected Gerber layers and Excellon drill files are produced and format-checked. The PDF was also rendered with Poppler and visually inspected. [Render](schematic-render.png). Gerber output uses explicit `--no-protel-ext`; the first fixture incorrectly assumed `.gbr` was the default and failed against legitimate Protel extensions.
- All original copied design/project bytes remain unchanged. KiCad creates a local `.kicad_prl` beside the copied input, even for these checks. Therefore importing/inspecting/checking must use private source copies, not original user paths.

The Rust report contract in `apps/desktop/src-tauri/src/kicad.rs` validates bounded reports, exact schema/version/source/units, all severity filters, findings and item UUIDs/coordinates. It rejects unknown fields, missing categories and contradictory exit outcomes. It counts active errors/warnings separately from excluded findings and preserves the list of disabled checks. Three regular tests replay these actual reports and reject malformed/forged variants. Excluded-finding classification currently has a synthetic fixture; actual excluded-marker runtime semantics remain unverified. All 57 regular backend tests and desktop/custom-protocol Clippy pass.

Reproduce after provisioning the identified private runtime and pinned QA inputs at `target/kicad-probe`: `rtk proxy python tests/kicad/runtime_probe.py`. The fixture creates a fresh UUID output and profile, uses fixed commands on copied files, asserts results and retains raw reports/help and hashes. Never infer a pass from process launch alone.
