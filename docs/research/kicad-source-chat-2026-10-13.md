# Initial KiCad checks from chat — October 13, 2026

The chat's existing saved schematic and PCB pickers now support a first native check/export without requiring a prior engineering job. Two new shared tools bring the host catalog to **24**. No editing form, new desktop IPC command or duplicate check runner is added.

## Source and approval boundary

`inspect_selected_kicad_check_source` resolves the human-selected capability, reads the complete supported source/dependency set with the existing capture reader, and returns the source name, kind, hash, source-set fingerprint, file count and export layers. It does not run ERC/DRC, create a job or write a discovery capture. Internal source paths, captured files and temporary metadata units are not exposed. Native source bytes are never rescaled. The agent asks what to review and confirms report units in mm, inches or mils.

`propose_selected_kicad_check` requires the inspected selection/fingerprint and explicit report units. The shared runner captures the source/dependencies again and compares the entire file set before preparing the human-only approval. Changed, removed or newly discovered dependencies require explicit reselection. Schematic ERC/PDF/netlist and PCB DRC/Gerber/drill derive from the selected source kind. PCB checking can refill zones and save its private checked copy; the open original is not edited. Findings remain separate from successful check execution. Existing `read_verified_result` and result-hash-bound `propose_kicad_check` provide subsequent checks from the actual saved result.

Saved KiCad selections now bind both project UUID and folder. Choosing another schematic, PCB or live PCB reading revokes old saved capabilities and their check-inspection cache. A shared SDK regression also reproduced the old MCP connection accepting calls after a copied-folder switch with the same UUID. MCP connection scope now includes the folder for every program and cancels a late unapproved proposal if the scope changes during a call. This is connection/source binding, not a claim of atomic live-document editing.
