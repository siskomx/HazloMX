# Native creation coordinate validation

A real existing Ollama Cloud conversation using the debug app from `51aadad` proposes the requested rectangular support with explicit mixed-unit dimensions, but also places `x`, `y` and `z` directly in `obj_properties`. These are not properties of the native FreeCAD box. The actual Hazlo approval permits dispatch; FreeCAD rejects the operation and verifies whole-transaction rollback. Native inspection and the unobstructed FreeCAD window confirm the document remains empty. The automatic uncertain-outcome review reads that state rather than claiming successful creation. All owned apps stop after evidence retention.

The focused regression reproduces the invalid coordinate reaching dispatch. The shared dispatch validator now refuses direct creation coordinates before proposal and again before native execution, with guidance to use native `Placement.Base` numeric millimetres. The tool description explains the native placement structure and permits omitting it when the origin is intended. Other operation schemas are unchanged. This is a targeted guard for the observed coordinate confusion, not complete property/type validation for every native operation.

Historical input validation stays unchanged so existing saved receipts remain readable. Tests cover each misplaced coordinate, the receipt-bearing dispatch path, valid nested placement, and refusal before any approval/job/history is created. All nine focused CAD tests, the workflow proposal regression, 20 regular host-tool tests and library/example Clippy pass; 12 environment-dependent host tests remain ignored. The debug app rebuild passes. Raw conversations, job data and observations remain private under ignored `target/`.

A fresh real existing Ollama Cloud run with the compiled guard and tool guidance then creates the same mixed-unit support after actual UI approval and raises its height to one inch after a second approval. Six independent native reads confirm the same document, unchanged geometry before each approval and final dimensions of 12.7 × 20 × 25.4 mm. Both completed schema-13 receipts verify. Complete geometry remains visible automatically after both edits. The creation and follow-up automatic reviews each use three ordinary-language sentences with dimensions and the unsaved state, without UUIDs, hashes or internal keys. This observes the final wording in one actual provider conversation; it does not guarantee all model responses or providers behave identically. The pre-approval description uses “centred at the origin” loosely even though the native box starts at the origin; exact position-description fidelity remains a wording limitation. No model file is saved, no exact model tool-call trace is retained, and both owned apps stop and join. This run does not test the installer.
