# CADCraft native drawing tools through chat

October 13, 2026. This source slice expands CADCraft beyond Hazlo's circle/conversion preset. The agent can inspect the identified program's command catalog and actual entity geometry, propose native `execute(command, params)` calls, obtain the existing one-use human approval, and read the program's saved result before a follow-up. Hazlo contains no new drawing editor or conversational operation parser.

The program is the existing identified official Windows x64 CADCraft 0.5.0 CLI, SHA256 `d9517678cf9216a63ecb7f4adfe4ab485af9541849d465245251bba91845724f`, from release commit `315751e3ec98e708bcc831dd7f80ca0433a2e3d0`. Its [MCP tool definitions](https://github.com/storytold/cadcraft/blob/315751e3ec98e708bcc831dd7f80ca0433a2e3d0/crates/mcp/src/tools.rs) describe the native `execute` contract and command discovery. The [drawing](https://github.com/storytold/cadcraft/blob/315751e3ec98e708bcc831dd7f80ca0433a2e3d0/crates/engine/src/cmd/draw.rs) and [modification](https://github.com/storytold/cadcraft/blob/315751e3ec98e708bcc831dd7f80ca0433a2e3d0/crates/engine/src/cmd/modify.rs) implementations provide the reviewed geometry commands. Parameter documentation comes from the actual identified binary's `commands` response; Hazlo does not substitute its own shape schemas. Native parameter validation remains in CADCraft, inside a private working copy after approval.

The new `inspect_drawing_native_tools` and `propose_drawing_native_tools` tools use the existing selected-source capability and shared Workflow. The nineteen-tool Hazlo catalog is available to both configured agent clients through the existing authenticated bridge. Native plans support the reviewed thirty-three geometry/selection command IDs, with up to sixteen calls, explicit original drawing units, a human-readable intent, and complete native entity inspection up to 128 entities. File operations, scripts, clipboard, document switching and UI commands are excluded from this path. Native save destinations remain reserved by the host. Oversized, truncated or ambiguous-scale work is refused instead of silently reduced.

The schema-3 approval record includes the native source entities as well as the proposed calls. Execution revalidates that source snapshot, invokes the approved commands in CADCraft, compares the native in-memory entity response with a fresh read of its saved DXF, and independently re-reads the final artifact. The report includes actual entities, command responses, summary and geometry hash. Report size is bounded to the existing agent readback limit. Native errors leave the working copy unpublished. Legacy drawing schemas 1/2, their circle proof and existing artifacts remain readable; new schema-3 reports cannot masquerade as legacy reports.

Verified on the current Windows host:

- `rtk cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --lib`: 120 passing tests; 46 native/environment gates remain ignored in that command.
- `rtk cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --lib actual_native -- --ignored --nocapture --test-threads=1`: actual identified CLI tests for catalog inspection, source-bound plans, approval/cancellation, a line plus a one-inch move in a millimeter drawing, rotation from the verified result, inch-native line/diameter input, saved geometry, forged-readback rejection, partial native failure/nonpublication, unchanged original/prior results and recovery. Approval is a backend test fixture.
- `rtk cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml --bins`: desktop and helper compile.
- `npm run build` and `node tests/chat-flow.mjs` in `apps/desktop`: production chat build and mocked IPC browser gate pass, including read-only source/proposed command review, escaped intent and explicit approval. These browser checks do not run a real agent or native application.

These tests exercise `line`, `move`, `rotate` and the native `circle` diameter form; they do **not** prove every parameter combination of all thirty-three catalog entries. The entity comparison establishes the native entity projection tested here, not full preservation of every annotation, layer, block, paper-space layout or constraint. Known import/export loss still requires explicit consent. Source files are never replaced by this saved-copy path. Raw logs, temporary paths, native reports and captures remain private.

This is **saved-file orchestration, not live window acceptance**. CADCraft's [control protocol](https://github.com/storytold/cadcraft/blob/315751e3ec98e708bcc831dd7f80ca0433a2e3d0/docs/control-protocol.md) supports a live window but needs actual process/document binding, approved dispatch and uncertain-write reconciliation before this goal's live gate is met. CADPilot's broad RPC interface and Arduino Agent's immediate saved-file writes also need their own document/effect boundaries. No new GUI connection, signed-in model turn, replacement installer, guest acceptance or hardware control is claimed. Native UI automation remains stopped after Escape. All other named program integrations and the full chat-to-native-tools goal remain active.
