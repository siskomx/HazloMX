# Native FCStd and STEP opening with GUI geometry readback

The current debug Hazlo WebView passes actual **Abrir FCStd** and **Abrir STEP** actions against FreeCAD 1.1.4. Each fixture copies the previously verified project into a fresh accented-path directory, preselects it through existing debug instrumentation, then clicks its native history button. An observer records an owned FreeCAD GUI process, its exact artifact argument and visible window. No model inference or hardware operation runs.

A read-only observer in a private FreeCAD startup module measures the actual active GUI document. FCStd opens the saved `Part::Box` with the exact native artifact filename. STEP opens an imported, unsaved `Unnamed` document containing `Part::Feature`. Both have one valid solid, dimensions 12.5 × 20 × 30 mm and volume 7,500 mm³, matching the completed job. The STEP name alone is not used as proof of import. [FCStd result](fcstd/result.json), [FCStd GUI readback](fcstd/gui-readback.json), [STEP result](step/result.json), [STEP GUI readback](step/gui-readback.json) and their recorded process arguments retain the evidence.

The observer only reads geometry and configuration and writes a test report; it neither creates nor edits the document. Its bounded timer stops after readback. The test uses existing [FreeCAD profile variables](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Start_up_and_Configuration.md#environment-variables) and the [documented startup-module mechanism](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Macro_at_Startup.md). The actual GUI reports both configuration and data directories inside the owned test profile. A separate identified CLI [profile probe](cli-profile-probe.json) also verifies those paths. Generated observer sources are retained with each case.

All engineering project hashes and recovered history remain unchanged after opening and reload. The live `.hazlomexa/writer.lock` is the only excluded operational file. The unavailable-runtime branch also passes again: the UI reports the opening error, with saved results and history intact. [Failure-path result](unavailable/result.json). Owned GUI, Hazlo, WebView and process-observer instances are closed; a final host process inventory confirms no remaining Hazlo/FreeCAD instance from these tests.

Failed observations are retained: [PowerShell output encoding](encoding-failure.json) initially corrupted the accented path; [STEP filename-title assumption](step-title-failure.json) incorrectly rejected its `Unnamed` import document; [observer initialization](observer-init-failure.json) did not yet deliver readback. The harness now explicitly emits UTF-8, registers the startup module and imports dependencies inside the timer callback's execution scope. Geometry/readback assertions establish the final success. Earlier failures are not counted as passing evidence.

Reproduce from `apps/desktop`: `rtk node tests/native-opening-failure.mjs <custom-protocol-debug-app.exe> <verified-FreeCAD-test-project> <FreeCADCmd.exe> [fcstd|step]`. Omit the runtime argument for the unavailable-runtime regression. The harness refuses to reuse a running FreeCAD GUI, uses its own profile and only stops observed GUI processes whose command line still identifies the owned project.

This verifies the native source app with debug project preselection. It does not establish native project/runtime picker acceptance, installed-release acceptance, signed-in chat, live unsaved-document tool access or broader CAD fidelity. The observer is a test fixture, not a new product agent API. The latest tested installer predates the empty FreeCAD draft change. The full application goal remains active.
