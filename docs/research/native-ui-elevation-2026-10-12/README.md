# Installed UI diagnostics identify an elevated test driver

Microsoft's [WebView2 contributor explanation](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5645) says Runtime 150 introduced hardening that drops debugging environment variables and HKCU overrides for elevated host processes. The [documented debugging environment](https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/debug-visual-studio-code) requires the application to inherit those variables. This provides a concrete explanation to investigate for the earlier refused guest CDP endpoints; it does not prove the historical app screen rendered.

The current startup test measures driver elevation before launching the app. An elevated driver writes an explicit failed prerequisite result (`elevated_host: true`, `app_started: false`), preventing another misleading debugger timeout. Unelevated host execution of the existing unbundled `0cdc30ad…` release passes actual native UI/read-only IPC: empty measurements, disabled proposal/approval, nine workflows and reload. [Host result](host-unbundled/result.json) is not installed acceptance and predates later source changes.

Fresh guest `e8cad335-79c8-4830-a06f-e48447a3a7b0` passes per-user installation, exact app/helper identities, fifteen-tool protocol, same-version update, process startup and project-preserving uninstall for that installer. The [lifecycle result](guest/package-result.json) retains **false** overall/native-UI status. Engineering harnesses were explicitly omitted for this UI-only diagnosis; their earlier proofs remain separate.

An experimental Explorer-delegated PowerShell driver first produced no status. The [prerequisite observation](guest/ui-prerequisites.json) shows restricted script policy and no live matching driver; after launching the owned script using the same content-invocation method as the existing Sandbox launcher, the [driver result](guest/ui-driver-result.json) and [native test failure](guest/startup/failure.json) confirm elevation remains true. This second run is a prerequisite diagnosis after uninstall, not an app test: its elevation guard refuses before spawning an app. The failed Explorer wrapper has been removed from the current harness; it did not solve this Sandbox's elevation.

The [experimental harness](experimental-explorer-probe.ps1), [diagnostic script](diagnose-owned-ui-driver.py), [current harness](current-package-harness.ps1), [test](installed-startup.mjs), [scope](fixture-scope.json), [package identity](package-identity.json) and [source hashes](source-hashes.json) retain the distinct observations. Node syntax, PowerShell parsing and the host native test pass. The guest is stopped; machine policies and application code were unchanged.

Installed native UI acceptance remains unfinished and needs a suitable unelevated driver/environment. Later measurement, context-reset, STEP and profile validation source changes also need an updated installer. The full application goal stays active; this diagnosis does not redefine completion.
