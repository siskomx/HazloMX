# FreeCAD working versions through the production host

The owned `owned_cadpilot_creation` acceptance example exercises the updated production shared-tool, approval, native RPC, copy verification, report and local recovery path with the existing portable FreeCAD 1.1.4 and CADPilot runtime. Its [sanitized acceptance record](native-working-version-chat-2026-10-19/acceptance.json) contains only bounded counts and boolean fixture facts. It uses a new isolated offscreen GUI process and disposable documents. Backend fixture approvals replace human UI approval; no AI service, user project or hardware is involved.

The native reader starts from an empty unsaved document. Missing creation dimensions are refused before a job exists. One reviewed native operation creates a box measuring 0.5 inches by 20 mm by 10 mm; another changes its height to 1 inch. A third checkpoint has no geometry operations. Every operation includes its own new native copy and independent pinned FreeCADCmd reopen. All three published reports remain readable and unchanged, and reopening the Hazlo project recovers all three completed batches without native calls. The shared result reader returns the validated copy identity, manifest digest, property/geometry checks, units, coordinate frame and dependency scope.

An independent GUI-thread check confirms the final native dimensions and volume. Two native Undo steps restore the previous height and then the empty document, confirming that copy capture and the checkpoint added no geometry edit or Undo entry. Native camera bounds contain the projected geometry, but this is an API calculation, not a rendered or visible-window check. The source document remains unsaved; the three new copies are separate outputs. All owned processes stop after each attempt.

The initial updated fixture incorrectly expected a checkpoint to invalidate its prior document hash. Capture intentionally preserves that hash, so the assertion applies only to geometry edits. That failed fixture preserved all three completed copies; subsequent acceptance uses a fresh disposable session. No production retry, rollback or replay is added for this correction. Raw native documents, observations, profiles and diagnostic output remain in ignored local test storage.

The result's `checks.native_working_version` is a host-validated historical proof summary, with an independent report scope. It does not claim a fresh live-document read, GUI fidelity, physical function or completion of the user's overall intended outcome. Scoped chat connections retain the entire reply locally before external delivery, including this summary. A sentinel case verifies that even the copy's filename is withheld until that exact reference is shared, and a service change does not inherit its grant. The summary is not declassified by projection or a successful reopen.

Validation also passes all 351 regular Rust tests (72 environment cases skipped), both desktop tests and all-target desktop Clippy. The existing frontend is unchanged by this checkpoint. The full plan remains active. This acceptance covers the supported self-contained FreeCAD primitives and actual native transport, not every model or program, a real AI conversation, human approval UI, the installed application or the Windows installer. Other program working versions, remaining outcome/setup/hardware/evidence boundaries and release acceptance remain required. No models are downloaded.
