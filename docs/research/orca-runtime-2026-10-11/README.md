# OrcaSlicer Windows package and slice-to-file gate

October 11, 2026. Official OrcaSlicer 2.4.2 x64 portable release, privately extracted into the owned test workspace. [Official release](https://github.com/OrcaSlicer/OrcaSlicer/releases/tag/v2.4.2), pinned commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`. [Identified package/binaries](identity.json), [actual slice command/result](slice-result.json), [effective selected profiles](machine.json), [process](process.json), [material](filament.json). This is a runtime gate, not an implemented Hazlo Mexa integration or fabrication certification.

The downloaded package is 171,367,668 bytes, SHA256 `feba3009dfb9d268779cca5758a1a5bc3b7d0722bf8fa48d5c57340de975d6be`, matching the current official release asset metadata and the earlier frozen source evidence. ZIP paths, size and symlink checks precede private extraction. The executable and OrcaSlicer DLL have no Authenticode signatures or version-resource values in this package. Package digest plus all extracted binary hashes identify it; the output 3MF metadata and G-code header independently identify OrcaSlicer 2.4.2. No global installer or printer/network plugin was installed.

Read-only discovery found two Windows-specific constraints. A minimal Python environment initially omitted SystemRoot because os.environ iteration exposes uppercase keys on Windows; explicit case-insensitive lookups and a private runtime/System32 PATH correct DLL initialization error 1114. `--version` is unsupported and returns an invalid-option error. `--help` returns zero but redirects streams to a console through the pinned source's `attach_console_on_demand`, so normal captured pipes contain no help text. Those results are retained [separately](discovery-calls.json), [version error](version.stderr.log). Zero exit alone is not a CLI-contract pass.

The actual file gate uses stock Prusa MK3S 0.4 nozzle, 0.20mm Standard process, and Prusa Generic PLA. The probe resolves each declared parent within the same stock category, rejects cycles/path escapes and writes flattened private profiles. Process compatibility, nozzle and layer height are checked. Post-processing scripts are refused. Bed type is explicitly **Textured PEI Plate**, preventing the unselected CLI default **Cool Plate** from silently determining the first-layer bed temperature. This selected reference configuration uses the upstream material's settings, not physical calibration for a user's printer. The initial unspecified-bed sample remains in the owned target history.

Fixed CLI arguments load those profiles, set a private data directory, slice an owned 10 mm cube, and export a 3MF to an owned output directory. `--export-3mf` receives only `Sliced.3mf`: the CLI prepends `--outputdir`, so an absolute export filename produces a duplicated invalid path. The initial failed path sample is retained in the owned target run. Inputs and profile overrides are reviewed gate fixtures; no production dispatcher is enabled.

Verified output: unchanged original STL; a 3MF containing one sliced G-code file; millimetre model units; 10×10×10 mm mesh bounds and twelve triangles; identity linear transforms (translations may arrange the model on the bed); exact effective machine/process/material names, 0.4 mm nozzle, 0.2 mm layers and selected bed; fifty generated layers with 10 mm maximum height; G21 and no active G20; embedded G-code MD5 match plus retained SHA256 of the archive and G-code. [Runtime output](stdout.log), [errors](stderr.log), [effective result and hashes](slice-result.json). Slicer placement is not a guarantee that original absolute mesh coordinates remain unchanged.

Reproduce with `rtk proxy python tests/orca/provision_runtime.py` in a fresh unprovisioned owned runtime directory, `rtk proxy python tests/orca/runtime_probe.py`, and `rtk proxy python tests/orca/slice_probe.py`. The provisioner refuses overwriting an existing runtime. Sources/models/profiles remain private test copies. No printer is connected and no firmware/G-code is sent to hardware.

Required next: typed backend source/profile capture, full compatibility and effective-setting validation, explicit input units and bed/material selection, approval preview including arrangement/settings, owned supervisor cancellation/deadlines, bounded 3MF/G-code verification, nonreplacing publication, recovery, UI/native/installed tests and second environment. This one reference profile combination does not establish all printer/profile families, custom-profile compatibility, import fidelity, multi-material slicing, headless editing or print safety. No OrcaSlicer application completion is claimed. The complete engineering application goal remains active.
