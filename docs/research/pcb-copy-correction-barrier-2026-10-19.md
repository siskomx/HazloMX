# Stop pending PCB copy calls on a correction

The existing PCB copy route now checks the chat dispatch barrier at native server startup, each admitted Konnect tool request and each KiCad verification/export process startup. This includes the verifier used by legacy PCB copy inputs. The shared gate is held through SDK request admission or native process startup and released before waiting for the reply. A correction pauses remaining dispatch without claiming that an admitted request was undone or that its effect is known. Missing completion links still preserve the copy and refuse replay.

Explicit pending-check recovery registers a busy operation under the original job, task and approved input before launching native checks. Stop and chat corrections reach that operation's barrier, including after reopening. A durable running record precedes launch; an unsuccessful recovery returns to interrupted state unless Stop recorded cancellation. Cleanup preserves retained proofs and releases the busy state. New native checks are withheld after a task correction, chat Stop, cancellation or a newer user instruction than the original approval. Linked results may still recover through the offline bookkeeping path. No consumed approval is restored and the copy writer is never part of recovery.

The targeted checks exercise a real owned synthetic CLI process and an in-process MCP transport. They show that the first admitted request can finish, correction does not wait for its reply, and the second request is not admitted. Another test checks that an already paused copy consumes no new check attempt. Workflow tests cover operation corrections, operation Stop, chat corrections and chat Stop, then reopen each task and verify that the pause and unchanged edit proof survive. These are host/transport checks; they do not constitute visual input automation or prove arbitrary server-side atomic conditions.

The [acceptance record](pcb-copy-correction-barrier-2026-10-19.acceptance.json) includes 396 passing desktop-enabled library/binary tests with 76 environment tests skipped; all-target desktop Clippy passes. The actual KiCad 10.0.7 copy fixture also passes against this source: two checked copies, an imperial follow-up, preserved originals, interrupted-check recovery without the editor/source/writer, preserved partial files and identical offline report reconstruction. Its supervised editor stops afterward. That fixture checks normal native operation/recovery; the correction cases above use the separate owned process, MCP transport and workflow fixtures. No frontend controls, native operations, provider or model download are added. Raw result sharing retains its existing task/recipient boundary.

The broader plan remains active: other typed copy pipelines still need the applicable correction/verification wiring, and generic MCP effect/concurrency guarantees remain distinct. Explicit approval to resume or expand a stopped copy, reconciliation of unlinked or manually changed copies, task-wide outcome review, hardware boundaries and Windows release acceptance remain unfinished. The installed application and installer are unchanged; KiCad 10 live schematics remains pending.
