# Continue checks of a retained PCB copy

New PCB copy approvals retain a separate edit/check journal. The journal is admitted before the copy edit; an immutable edit checkpoint is linked only after the native Konnect acknowledgment, whole-board move/dependency checks and owned process closure succeed. It binds the approved input, original attempt, owned directory identity and exact edited file manifest. The final report hash is separate. Legacy inputs omit the new fields and preserve their original identities and validation.

If later checking fails, `recover_native_result` validates the same retained edited copy and completes only its KiCad checks. It never starts Konnect, repeats the move, reconnects to the original editor or substitutes today's saved source. Compatible installed KiCad CLI can be detected automatically after reopening. Native verification uses a new admitted directory for each of at most two check attempts; earlier partial files remain local and are not presented as verified outputs. The approval explains this bound and the existing copper-zone refill in verification copies. A session-local OS mutex prevents simultaneous recovery of the same job from exceeding those bounds.

Each successful native check has its own linked report digest. The final result identifies its selected verification directory; artifact paths and follow-up sources use that checked version. Already linked checks can reconstruct only the identical final report without any native program. Startup recovery performs that local bookkeeping/publication path and never launches new checks. A cancelled job allows only offline completion; the chat does not automatically resume native steps after Stop.

Missing edit/check links do not adopt plausible files. Changed native inputs, edited files, dependencies, identities, conflicting reports and exhausted bounds preserve work and pause. A native write or its process closure that was never durably confirmed still requires later explicit reconciliation; this route does not infer its cause from current geometry. Manual edits to a retained copy are not overwritten or silently accepted as the earlier result. Explicit resumption after Stop, expanded check allowances and a newly approved checkpoint after an unlinked/changed copy remain separate pending work.

The result and its revealing derivatives remain behind the existing task/recipient evidence-sharing gate. Progress summaries disclose no source bodies. Journal/proof files and partial attempts stay local; no model is downloaded. Successful checking does not establish GUI fidelity, electrical correctness, physical function or the whole agreed task outcome.

Validation exposed a shared Windows process-cleanup race: the parent and log pipes could close while an owned descendant still ran. After requesting termination, the synchronous native process helper now waits up to five seconds for its job's active-process count to reach zero, or returns an error. It does not report successful process closure merely from the parent's exit. This follows Windows' [job termination](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject) and [job accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information) facilities. The regression includes a completed parent whose child has independent log handles; unrelated processes remain outside the owned job. Other asynchronous transport/supervisor shutdown routes retain their existing checks and are not certified by this change.

The actual native-window fixture passes two checked copies and an imperial follow-up. It then closes the editor, removes the owned original source temporarily, preserves the first check's files while withdrawing its completion link, and reopens the job as interrupted. Startup refuses to adopt that plausible unlinked check. A fresh host with no Konnect writer detects KiCad CLI, verifies the same linked edit in a second directory, preserves the partial attempt, publishes the result and restores follow-up access. The original edit checkpoint stays identical. Removing only the linked final report then demonstrates identical offline reconstruction through startup recovery. The supervised editor stops afterward. This is controlled failure injection around a real native edit/CLI check, not a real-provider conversation or arbitrary crash/hardware acceptance.
