# PCB SDK held-read cancellation and full deadline

The separate [busy host-read gate](../pcb-busy-read-2026-10-13/README.md) refuses a Windows oplock during Rust's board pre-read. This gate instead reaches the actual get_board_info SDK read after that pre-read, then holds the staged board until shutdown has completed. A cfg(test)-only checkpoint in the already owned profile signals readiness, waits for the fixture to acquire its NTFS barrier and resumes the same dispatch operation. The checkpoint and controls are omitted from release builds. It does not replace the SDK, change the operation timer, inject a fake result or grant approval.

Both actual approved PCB workflows pass using identified Konnect 0.13.0 and KiCad 10.0.7 on host Windows 11 Pro build 26200. They consume one-use approval, observe the owned Konnect PID alive at the held access, then either cancel or wait for the production sixty-second tool deadline. The owned server ceases before barrier release. Cancellation returns its terminal view within the existing one-second bound and finishes worker shutdown within ten seconds; timeout returns a separate Failed result. Neither publishes an artifact/result or changes the staged board/original source files. Reopening recovers the single Cancelled/Failed run with files_verified false.

This is SDK read interruption before the board mutation. It does not assert a particular mutation phase, native KiCad CLI interruption, native GUI interaction, installed or signed-in acceptance. The checkpoint exists to avoid mistaking a held host pre-read for a blocked native SDK read. It adds only test instrumentation; comparison with the preceding busy-read source verifies the release portions of jobs.rs/konnect_run.rs are unchanged after removing the cfg(test) checkpoint. The b61f94df installer/app/helper identities remain unchanged and retain their previous package scope. No new package build was needed for these tests.

Reproduce with `rtk proxy python tests/konnect/verify_blocked_read.py --pcb-sdk` (or add --cancel-only for the cancellation case). --pcb remains the separate prompt host-read refusal; --workflow remains the schematic interruption cases. The verifier freezes source, runtime and input fixture hashes, requires two exact passing test markers and checks approval, observed PID shutdown, preserved copies, nonpublication, phase and recovery receipts. Zero/ignored cases and changed inputs cannot pass. Exact source, logs, inputs, controls, staging and receipts are retained here.

The regular parallel run had one existing process timing test exceed its unchanged five-second bound while the host had less than a GiB free; 115 passed/one failed/41 ignored. No timing limit or assertion was relaxed. Serial validation passes all 116 regular tests with 41 separately scoped ignored entries, and Clippy for all targets passes with warnings denied. The serial console log is retained; initial parallel and Clippy results are recorded from the tool session, not claimed as captured logs. This does not prove normal parallel timing under sufficient memory.

Native UI automation stays stopped after the user's interruption. Windows guest execution still needs its existing three-GiB free-memory prerequisite. No model evaluation, paid inference, hardware mutation or host-global configuration changed. The full application goal remains active.
